# Content

<Callout type="info">
  `Content` is not `Contents`. [Contents](/docs/contents) is the table of
  contents from the Manifest's Ranges.
</Callout>

The Root's current view, drawn: a page, a spread, a video or sound.
[`Canvas`](/docs/canvas) draws it, unless a renderer of your own claims the view.
`Content` gives it a height, shows Clover's loading mark while the Root loads, and takes
your controls. The templates draw it; in a layout of your own, place it anywhere inside a
`Clover.Root`. It reads the Root, so it cannot stand on its own.

```jsx
import * as Clover from "@nulib/clover";
import "@nulib/clover/styles.css";

<Clover.Root iiifContent={manifestUrl}>
  <Clover.Content />
  <Clover.Items />
</Clover.Root>;
```

## Its height

The Canvas fills its parent, and `Content` is that parent. Its height is
`var(--clover-content-height, 60vh)`, set inline, so it holds without the stylesheet. Set
the property on `Content` or on any element round it; `100%` fills a parent that has a
height of its own.

```css
.my-layout {
  --clover-content-height: 70vh;
}
```

`style` is merged over the inline height, so a `height` given there wins.

## Controls of your own

Children join the Canvas's controls, after Clover's own. Over a placeholder, and over a
lone video or sound, where Clover's image controls are left out, the controls stay for
yours. `PanelToggle` is made for this place:

```jsx
<Clover.Content>
  <Clover.PanelToggle
    open={panelOpen}
    onOpenChange={setPanelOpen}
    controls="panel"
  />
</Clover.Content>
```

See [Showing and hiding it](/docs/panel#showing-and-hiding-it) on the Panel page for
the rest. A control of your own names itself as Clover's do: see
[Controls of your own](/docs/composing#controls-of-your-own).

## Renderers of your own

Give `Content` or the `Root` `renderers`, and a view one of them claims is drawn by your
component in place of the Canvas: a 3D model, a PDF, anything a Canvas paints that Clover
does not draw. A renderer claims a view by a Canvas id, by a painted body's `format`, or
with a `match` test. The first that claims it draws it; every other view is the Canvas's.

```jsx
function ModelViewer({ bodies }) {
  return <model-viewer src={bodies[0].id} camera-controls />;
}

const modelRenderers = [
  { format: ["model/gltf-binary"], component: ModelViewer },
];

<Clover.Root iiifContent={manifestUrl} renderers={modelRenderers}>
  <Clover.Content />
</Clover.Root>;
```

The component renders inside the Root, so Clover's hooks work in it (`useNavigation`,
`useActiveCanvas`, `useClover`…). It is given the view's `canvases`, the `bodies` they
paint (a `Choice` as its first item, a `SpecificResource` as its source) and `Content`'s
`children`, its controls, to place where it likes.

A `Content`'s own `renderers` stand in place of the Root's: `renderers={[]}` leaves every
view in that one to the Canvas. A list written inline, equal on each render, does not
remount the renderer. `.clover-content` carries `data-renderer`, `canvas` or `custom`, for
your CSS to select. [Composing Layouts](/docs/composing#renderers-of-your-own) maps 3.x's
`customDisplays` onto `renderers`.

### `ContentRenderer`

| Prop        | Type                                        | Description                                            |
| ----------- | ------------------------------------------- | ------------------------------------------------------ |
| `canvasId`  | `string[]`                                  | Draws a view showing one of these Canvases.            |
| `format`    | `string[]`                                  | Draws a view painting a body of one of these formats.  |
| `match`     | `({ canvases, bodies }) => boolean`         | Draws any view this says yes to.                       |
| `component` | `React.ComponentType<ContentRendererProps>` | What draws it: given `canvases`, `bodies`, `children`. |

## Loading

While the Root loads (its first Manifest, or another it moves to, from a Collection say),
`Content` is `aria-busy`. Clover's loading mark, a 3px line in the accent, runs along its
top edge, over what it still shows. It takes no room and catches no presses, and
`Content` keeps its size and its background, so nothing moves. The mark waits a quarter
of a second before it shows, so a quick load never flashes it, and it draws more slowly
for a reader who asks for less motion.

The mark is decorative (`aria-hidden`). To announce the load, place a `Status` with
`loading={false}`: it announces "Loading…" and shows nothing, since `Content` shows it.

```jsx
<Clover.Root iiifContent={manifestUrl}>
  <Clover.Status loading={false} />
  <Clover.Content />
</Clover.Root>
```

## `Canvas` or `Content`

`Content` draws the view with `Canvas`, connected to the Root. The Canvas's name is the
current Canvas's label, or the Manifest's; its annotations, its chapters (from the
Manifest's Ranges), its language and its request settings are the Root's. Pass `label`,
`annotations`, `chapters` or `language` to `Content`, or `options.request`, to give your
own. `Canvas` alone in a Root shows the same view, without the height, the renderers and
the loading mark. See [`Canvas` or `Content`](/docs/canvas#canvas-or-content).

## Props

| Prop        | Type                  | Description                                                |
| ----------- | --------------------- | ---------------------------------------------------------- |
| `renderers` | `ContentRenderer[]`   | Renderers for this `Content` only, in place of the Root's. |
| `style`     | `React.CSSProperties` | Merged over its inline height.                             |
| `className` | `string`              | Added to `clover-content`.                                 |
| `children`  | `ReactNode`           | Controls, after the Canvas's own; a renderer's `children`. |

Its other props are [Canvas's](/docs/canvas#props) (`controls`, `navigator`, `options`,
`onReady`, `onViewportChange` and the rest), and go to the Canvas. `canvases`, `body`,
`src`, `isTiledImage` and `viewingDirection` are not among them: they come from the Root.
A view a renderer of yours draws takes none of them.

### `Root`

| Prop        | Type                | Description                                                  |
| ----------- | ------------------- | ------------------------------------------------------------ |
| `renderers` | `ContentRenderer[]` | Renderers for every `Content` inside, unless it has its own. |

## From Clover 3.x

| 3.x `Viewer`                       | Clover 4                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| `options.canvasHeight` (`500px`)   | `--clover-content-height` (`60vh`)                         |
| `canvasHeight: "auto"` or `"100%"` | `--clover-content-height: 100%`, in a parent with a height |
| `customDisplays`                   | `renderers`, on `Content` or `Root`                        |
