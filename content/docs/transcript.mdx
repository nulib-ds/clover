## API reference

Inside a `Root`, it reads the view's WebVTT files and any transcript as plain text,
with a choice where there are several, and renders nothing where there is neither. A
WebVTT file is what its annotation `provides` (Presentation 4): captions or subtitles,
which the Canvas shows too, or a transcript alone, which the Transcript reads and the
Canvas never offers as captions. It reads the file in the Root's language where there is one, the Canvas's captions with it,
and where the Root offers the languages to read the resource in (About's), it offers none
of its own: the page has one choice of language. Over
the captions, a field finds words as they are typed: the cues with them marked and
counted, the first current, and Previous, Next or Enter going through them, each seeking
the recording there. A long transcript is drawn a chunk of cues at a time, more as the
reader nears its end.
`Default` and `Document` show it in their [Panel](/docs/panel). Its other props, and its
`ref`, go to its element.

<ApiReference elements="clover-transcript">

| Prop        | Type                 | Default   | Description                                                                                  |
| ----------- | -------------------- | --------- | -------------------------------------------------------------------------------------------- |
| `follow`    | `boolean`            | `true`    | Keep the cue playing in view while the media plays.                                          |
| `find`      | `boolean`            | `true`    | A field over the captions to find words in them, with steps through the cues that have them. |
| `sticky`    | `boolean`            | `false`   | The find field held in view as the cues scroll under it.                                     |
| `size`      | `"large" \| "small"` | `"large"` | The find field's size, as Search's: a tad smaller for a narrow column.                       |
| `as`        | element type         | `"div"`   | The element to render, such as a `section`.                                                  |
| `className` | `string`             | —         | Added to `clover-transcript`.                                                                |

</ApiReference>

## Examples

### Scroll in a box

Give it a height, and it scrolls in a box of its own. Make the box a named region the
keyboard can reach, as here (WCAG 2.1.1).

<Example>
<PartDemo
  part="Transcript"
  resource="footage"
  body
  props={{
    as: "section",
    "aria-label": "Transcript",
    tabIndex: 0,
    style: { maxHeight: "20rem", overflowY: "auto" },
  }}
/>

```jsx
<Clover.Transcript
  as="section"
  aria-label="Transcript"
  tabIndex={0}
  style={{ maxHeight: "20rem", overflowY: "auto" }}
/>
```

```html twin
<!-- The element is a box no reader is told of: the page's own region names and scrolls it. -->
<section
  aria-label="Transcript"
  tabindex="0"
  style="max-height: 20rem; overflow-y: auto"
>
  <clover-transcript></clover-transcript>
</section>
```

</Example>

### Leave the scrolling to the reader

Use `follow={false}` to leave the scrolling to the reader. The cue playing is still
marked.

```jsx
<Clover.Transcript follow={false} />
```

</Example>

### A transcript of your own

Clover's WebVTT parser is exported: `parseVtt` reads a file's cues, and `cueAt` finds the
one playing.

```js
import { cueAt, parseVtt } from "@nulib/clover";

const cues = parseVtt(await (await fetch(vttUrl)).text());
const index = cueAt(cues, video.currentTime);
const words = index >= 0 ? cues[index].text : "";
```
