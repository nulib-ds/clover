# Helpers

<div className="docs-lede">
  Clover's helpers are yours too. Functions read IIIF resources, events say what
  changed, hooks read the nearest `Root`, and the template helpers build a
  template of your own.
</div>

## IIIF resources

These come from `@nulib/clover`, for code you bundle. The web components' script from a
CDN leaves them out.

| Helper                                    | Description                                                                                                                                                                                                                                           |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `toPresentation4(resource)`               | Upgrades a Manifest, Collection, Canvas, Timeline or Scene from an earlier Presentation version to Presentation 4, the version Clover works in throughout: a Root upgrades what it loads the same way. A Presentation 4 resource comes back as it is. |
| `readAs(format, value)`                   | Tells you whether a value, such as a `summary` or an annotation's `TextualBody`, is `"html"`, `"markdown"` or `"plain"`. It reads the `format` media type, or IIIF's rule when there's none.                                                          |
| `toPlainText(html)`                       | Turns a IIIF HTML value into plain text, for an `alt` or an `aria-label`, where markup can't go.                                                                                                                                                      |
| `localize(value, language)`               | Picks the text of a IIIF language map, such as a `label`, in `language`, or the closest it has. Returns `{ text, lang }`, several values joined with commas.                                                                                          |
| `thumbnailSource(resource)`               | Finds the thumbnail of a Manifest, Collection or Canvas: its own `thumbnail`, or else the first image a Canvas paints. Returns `null` when it has neither.                                                                                            |
| `stillSource(canvas)`                     | Finds a picture to stand in for a Canvas at the size it's drawn: the first image it paints, else its placeholder's or accompanying Canvas's, and only then its own `thumbnail`, which is often small.                                                 |
| `regionSource(canvas, { x, y, w, h })`    | Finds an image of one region of a Canvas, in its own coordinates, such as an annotation's `xywh`. Returns `null` when no IIIF Image service is painted there.                                                                                         |
| `resolveThumbnail(source, size, request)` | Turns what `thumbnailSource` or `regionSource` found into an image URL, about `size` pixels on its longer side (200 if you leave it out). It asks only for sizes the image's `info.json` allows.                                                      |
| `buildContentState(view)`                 | Writes a [content state](/docs/content-state) annotation that targets a Canvas in a Manifest, and a `region` or `time` on it if you give one. Returns it as `json` and `encoded`.                                                                     |
| `encodeContentState(json)`                | Encodes a content state annotation you wrote yourself, for a link's `iiif-content` parameter.                                                                                                                                                         |
| `decodeContentState(value)`               | Decodes an `iiif-content` value back into its annotation. Returns `null` when it isn't one.                                                                                                                                                           |
| `groupViews(canvases, behavior)`          | Groups a Manifest's Canvases into the views the Viewer shows: one Canvas each, two for a spread in a `paged` Manifest (the first alone, as a cover), or all of them for `continuous`. Each view is a list of the Canvases' indexes.                   |
| `resolveBehavior(behavior)`               | Reads a `behavior` for the value that lays out a sequence: `individuals` (the default), `paged`, `continuous` or `unordered`.                                                                                                                         |
| `resolveDirection(viewingDirection)`      | Reads a `viewingDirection`: `left-to-right` (the default), `right-to-left`, `top-to-bottom` or `bottom-to-top`.                                                                                                                                       |

## Maps

These read where a IIIF resource is, for a [Map](/docs/map) or a map of your own. They
come from `@nulib/clover/map` and `@nulib/clover`.

| Helper                                       | Description                                                                                                                                                                                    |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hasMapData(manifest, collection)`           | Tells you whether a Manifest, or the Collection it's in, has anything to put on a Map: a `navPlace`, a GeoJSON annotation body or a georeferencing annotation.                                 |
| `canvasHasMapData(canvas)`                   | Tells you whether one Canvas has a place of its own: its `navPlace`, an annotation's, a GeoJSON annotation body or a georeferencing annotation.                                                |
| `navPlaceOf(manifest, collection, language)` | Gathers every `navPlace` of the Collection, the Manifest, its Canvases and their loaded annotations into one GeoJSON FeatureCollection, each place named by what it belongs to, in `language`. |
| `georeferencesOf(manifest)`                  | Gathers the georeferenced images of the Manifest's Canvases, from their loaded annotation pages.                                                                                               |
| `readGeoreference(annotation, canvas)`       | Reads one Georeference Extension annotation as an image to lay over the Map: its control points, extent, mask and image. Returns `null` when it can't be drawn.                                |
| `boundsOf(features, georeferences)`          | The `[[west, south], [east, north]]` box that holds places and georeferenced images. Returns `null` for none.                                                                                  |
| `cornersOf(georeference)`                    | Where a georeferenced image's corners land, as `[longitude, latitude]`: top left, top right, bottom right, bottom left.                                                                        |
| `affineTransform(points)`                    | The transform that best fits a georeference's control points, from image pixels to `[longitude, latitude]`. Returns `null` when the points lie on one line.                                    |
| `setMapWorkerUrl(url)`                       | Serves MapLibre's worker from an address of your own ([Map](/docs/map#maplibres-worker)).                                                                                                      |

### Map example

These read Northwestern's _Map of the Township of Evanston, Cook County, Illinois_. Each
result is in the comment under it, rounded.

```js
import {
  boundsOf,
  cornersOf,
  georeferencesOf,
  hasMapData,
  navPlaceOf,
  toPresentation4,
} from "@nulib/clover";

const url =
  "https://clover.iiif.library.northwestern.edu/mocks/georeference/manifest.json";
const manifest = await toPresentation4(await (await fetch(url)).json());

hasMapData(manifest);
// true: it has something to put on a map

const places = navPlaceOf(manifest);
// A FeatureCollection with one place, "Evanston, Illinois",
// a Point at [-87.6877, 42.0451]

const [georeference] = georeferencesOf(manifest);
// The scanned map: its control points, width, height, label and image

cornersOf(georeference);
// Where its corners land, as [longitude, latitude]:
// [
//   [-87.7177, 42.0777], top left
//   [-87.6241, 42.0754], top right
//   [-87.6272, 41.9877], bottom right
//   [-87.7208, 41.99], bottom left
// ]

boundsOf(places.features, [georeference]);
// The box around them all, [[west, south], [east, north]]:
// [[-87.7208, 41.9877], [-87.6241, 42.0777]]
```

## Events

What React hands a callback, an element sends as an event: `clover-` and what happened,
bubbling, so a page can listen for it anywhere above the element. Its `detail` holds what
the callback is given.

| React prop             | Event                         | `detail`                                                                        |
| ---------------------- | ----------------------------- | ------------------------------------------------------------------------------- |
| `onCanvasChange`       | `clover-canvas-change`        | `{ canvasId }`                                                                  |
| `onManifestChange`     | `clover-manifest-change`      | `{ manifestId }`, in a Collection                                               |
| `onStatusChange`       | `clover-status-change`        | `{ status, error }`, as it loads                                                |
| `onContentStateChange` | `clover-content-state-change` | `{ json, encoded }`, as the view changes ([Content State](/docs/content-state)) |
| `onSearchChange`       | `clover-search-change`        | `{ query }`, as a search runs, or `""` once it is cleared                       |

<div data-code-flavor="web-components">

```js
viewer.addEventListener("clover-canvas-change", (event) => {
  console.log(event.detail.canvasId);
});
```

`<clover-root>` sends the same events as `<clover-viewer>`; `<clover-items>` and
`<clover-map>` send `clover-select` when an item or a place is chosen (cancel it, with
`preventDefault`, to keep a link from being followed), `<clover-collection-select>` sends
`clover-change`, and `<clover-root>`, `<clover-body>` and `<clover-canvas>` send
`clover-ready`: a root's `clover` then reads it, as the [hooks](#hooks) below do, and a
Body's or Canvas's `handle` moves its view (`body.handle.zoomBy(2)`). `clover-ready` is
the element's own and does not bubble, as `load` does not.

</div>

## Hooks

These come from `@nulib/clover`, for components of your own inside a `Root`. Each
re-renders only when what it reads changes.

| Hook                                 | Returns                                                                                                                                                                                  |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useStatus()`                        | `{ status, error }`                                                                                                                                                                      |
| `useManifest()`                      | The Manifest, in Presentation 4.                                                                                                                                                         |
| `useSequence()`                      | `{ canvases, views, direction }`                                                                                                                                                         |
| `useVisibleCanvases()`               | The Canvases of the current view.                                                                                                                                                        |
| `useActiveCanvas()`                  | The current Canvas.                                                                                                                                                                      |
| `useNavigation()`                    | `{ position, total, hasPrevious, hasNext, previous, next, first, last, goTo }`                                                                                                           |
| `useAnnotationCollection()`          | Annotations walked as one whole, the content's AnnotationPage or the Manifest's AnnotationCollection: `{ id, type, label, total, pages, entries }`, or `null`.                           |
| `useLocalized(value)`                | `{ text, lang }` for a IIIF language map, in the Root's language.                                                                                                                        |
| `useT()`                             | `t(key, values)`: the predefined strings, in Clover's interface language.                                                                                                                |
| `useLangOf()`                        | `langOf(key)`: a string's `lang` where it is not the page's language.                                                                                                                    |
| `usePanelSections(names?)`           | Which of a `Panel`'s default sections this resource has data for, in the panel's order, narrowed to `names`: none of them, and a `Panel` would draw nothing.                             |
| `useAnnotationPages({ listed })`     | Each AnnotationPage the Manifest's Canvases carry, and each the `Root`'s `annotations` adds: its `id`, `label` and annotations (`entries`). With `listed`, only those Annotations lists. |
| `useCloverSelector(select, isEqual)` | Any value from the Root's state, by `select`, re-rendering only when it changes. `isEqual` compares it, where `select` returns a new object each time.                                   |
| `useUniqueId()`                      | An id unique on the page, as Clover uses wherever it needs one.                                                                                                                          |

`useClover()` gives the Root's state and actions, for components that act rather than
read.

Each example below is a component of its own in a Root, under its Body, most over the
IIIF Cookbook's book (recipe 0009). Its comments show the first view.

<div data-code-flavor="web-components">

As web components, the root's `clover` has a method for each hook but `usePanelSections`
and `useUniqueId`, and `subscribe` hears of every change.

</div>

### `useStatus()`

Whether the Root is loading, ready or has failed.

<Example>
<StatusDemo />

```jsx
import * as Clover from "@nulib/clover";

function Status() {
  const { status, error } = Clover.useStatus();
  // status: "ready"
  // error: null

  return <p>{error ? error.message : status}</p>;
}

<Clover.Root iiifContent="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json">
  <Clover.Body style={{ height: "12rem" }} />
  <Status />
</Clover.Root>;
```

```html twin
<script type="module">
  import "@nulib/clover/web-components";
</script>

<clover-root
  iiif-content="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json"
>
  <clover-body style="height: 12rem"></clover-body>
  <p id="status"></p>
</clover-root>

<script type="module">
  const root = document.querySelector("clover-root");
  const shown = document.getElementById("status");
  // { status: "ready", error: null }
  const show = () => (shown.textContent = root.clover.status().status);
  const start = () => {
    show();
    root.clover.subscribe(show);
  };
  if (root.clover) start();
  else root.addEventListener("clover-ready", start, { once: true });
</script>
```

</Example>

## Templates

<div data-code-flavor="react">

Clover's templates are built from the components in `@nulib/clover` and a few helpers
from `@nulib/clover/templates`. Your template can use them too.

### Change a template

The same four steps work for Default, Document and Gallery:

1. On GitHub, open the [tag](https://github.com/nulib-ds/clover/tags) for the version you
   have installed, and copy the template's folder from `packages/clover/src/templates/`
   into your app.
2. In the files you copied, change `../../parts` to `@nulib/clover`, and each
   `../shared/…` to `@nulib/clover/templates`.
3. Rename the template's component (`Default` to `MyViewer`, say), then change what you like.
4. Import its CSS after `@nulib/clover/styles.css`, and pass it to the Viewer as its
   `template`.

```jsx react
import Viewer from "@nulib/clover";
import "@nulib/clover/styles.css";
import { MyViewer } from "./MyViewer";
import "./MyViewer.css";

<Viewer iiifContent={url} template={MyViewer} />;
```

Your CSS wins over Clover's. A copy of Document or Gallery also needs
`@nulib/clover/templates.css`, for the Lightbox.

### Panel

Every template places its Panel beside the Body where there is room, and over it where
there isn't. `usePanelPane` keeps its state and `PanelPane` draws it, as the
[Custom Panel example](#custom-panel-example) shows.

#### `usePanelPane()` options

```js
import { usePanelPane } from "@nulib/clover/templates";
```

Call `usePanelPane` in your template with these options (`PanelPaneOptions`):

| Option        | Type                                     | Default            | Description                                                                                                                                                                                                        |
| ------------- | ---------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`          | `string`                                 | Required           | The Panel's `id`, which its PanelToggle's `aria-controls` names.                                                                                                                                                   |
| `beside`      | `boolean \| undefined`                   | Required           | Whether there's room for the Panel beside the Body. Pass `useWideEnough(split, BESIDE_REM)`. Until it's measured, the Panel is beside the Body.                                                                    |
| `defaultOpen` | `boolean`                                | Required           | Whether the Panel starts open beside the Body. Over the Body, it always starts closed.                                                                                                                             |
| `followFocus` | `ReturnType<typeof useFollowFocus>`      | Required           | Pass `useFollowFocus()`, one per template, so focus follows the PanelToggle as it moves.                                                                                                                           |
| `side`        | `"start" \| "end"`                       | `"end"`            | The Body's side the Panel sits on, and slides in from when it's over the Body.                                                                                                                                     |
| `sections`    | `PanelSection[]`                         | Every section      | Which of the Panel's sections it may offer. With none that the Manifest has data for, there's no Panel and no PanelToggle.                                                                                         |
| `body`        | `() => HTMLElement \| null \| undefined` | —                  | Finds the Body, so the PanelToggle on the SplitHandle lines up with the Body's top.                                                                                                                                |
| `panel`       | `ComponentType<PanelProps>`              | Loaded when needed | `Clover.Panel`, to draw the Panel at once, on the server too. Without it, the Panel's code loads right away when it starts open, and once its PanelToggle is pointed at, focused or pressed when it starts closed. |

#### `usePanelPane()` returns

It returns the Panel's state (`PanelPaneState`). A template uses these:

| Name         | Type                      | Description                                                                                                                                                                               |
| ------------ | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`       | `boolean`                 | Whether the Panel is open.                                                                                                                                                                |
| `over`       | `boolean`                 | Whether the Panel is over the Body, as there's no room beside it.                                                                                                                         |
| `docked`     | `boolean`                 | Whether the Panel is open beside the Body. Its PanelToggle then sits on the SplitHandle.                                                                                                  |
| `toggle`     | `ReactElement`            | The PanelToggle. Put it in the Body while the Panel isn't open beside it: `{!pane.docked && pane.toggle}`.                                                                                |
| `splitProps` | `object`                  | Spread on the Split. It tells the Split where the Panel is, closes the Panel with Escape while it's over the Body, and starts loading the Panel's code as its PanelToggle is reached for. |
| `setOpen`    | `(open: boolean) => void` | Opens or closes the Panel.                                                                                                                                                                |
| `close`      | `() => void`              | Closes the Panel.                                                                                                                                                                         |

Give the Split the class `clover-template-panes`, which styles the Panel over the Body.

#### `PanelPane` props

```js
import { PanelPane } from "@nulib/clover/templates";
```

`PanelPane` draws the Panel in a SplitPane of its own. Place it after your main
SplitPane, or before it on the `"start"` side:

| Prop        | Type             | Default  | Description                                                                                                                                                                 |
| ----------- | ---------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pane`      | `PanelPaneState` | Required | What `usePanelPane` returns.                                                                                                                                                |
| `className` | `string`         | —        | A class for the Panel's SplitPane, beside `clover-template-panel`.                                                                                                          |
| …           |                  |          | Any of the [Panel's props](/docs/panel), such as `layout`, `headingLevel`, `sections` or `Clover.Tab` children. Not `onClose` or `closeOnEscape`: `PanelPane` handles them. |

### Room beside the Body

| Helper                    | Description                                                                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useWideEnough(ref, rem)` | Tells you whether the element `ref` points to is at least `rem` wide, and checks again as it resizes. `undefined` until it's measured.                                     |
| `BESIDE_REM`              | How wide, in rem, a template must be for the Body and the Panel side by side: `PAGE_MIN`, `PANEL_MIN` and the SplitHandle. Any narrower, and the Panel goes over the Body. |
| `PAGE_MIN`, `PANEL_MIN`   | The narrowest the SplitHandle may drag the Body and the Panel, as CSS lengths.                                                                                             |

#### `useWideEnough()` example

Each result is in the comment under it.

```jsx react
import { useRef } from "react";
import {
  BESIDE_REM,
  PAGE_MIN,
  PANEL_MIN,
  useWideEnough,
} from "@nulib/clover/templates";

BESIDE_REM;
// 31: PAGE_MIN, PANEL_MIN and the SplitHandle between them, in rem

PAGE_MIN;
// "16rem"

PANEL_MIN;
// "14rem"

function Room() {
  const box = useRef(null);

  const wide = useWideEnough(box, BESIDE_REM);
  // undefined until the box is measured, then true or false as it resizes

  return (
    <div ref={box}>
      {wide === false
        ? "The Panel goes over the Body."
        : "The Panel fits beside the Body."}
    </div>
  );
}
```
