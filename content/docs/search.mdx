## API reference

Inside a `Root`, it searches the Manifest through its Content Search service, version 1 or
2, and lists the hits by Canvas, each with the words around it, from up to 10 pages of
results. Choosing a hit goes to it and frames it, and every hit is drawn on the Canvas.
Inside the field, before its clear, Previous and Next step through the hits in order, across Canvases,
showing which is current over the total ("3 / 11"); results go to their first hit as
they arrive, as find in a page does, starting from the current Canvas: its first hit, where
it has hits, else the first of all. So a page opened with a query (a content
state and a `searchQuery`, from a site's search results) stays on that page. With `sticky` the field is held in
view as the hits scroll; the Panel's own Search section has it, and draws its hits on the
Canvas only while it is open. The page's own text, its OCR, is not drawn until a
search finds something in it; without a search service, the Canvas's annotations menu
offers it instead ([Searching supplementing annotations](#searching-supplementing-annotations)). In a Panel, a search started outside its Search section
opens it ([The open section](/docs/panel#the-open-section)). It renders nothing without a
search service. Its other props, and its `ref`, go to its
element.

## Examples

### A query to start with

Use `searchQuery`, on the Viewer or a `Root`, to search as the Manifest opens and again
whenever it changes. The Viewer draws the hits on the Canvas and lists them in its Panel's
Search section. `onSearchChange` hears each query as it changes, one typed in the Search
field too, and `""` once it is cleared, so a page can keep it in its address, as the
homepage does with `?q=`.

<ViewerExample resource="search" props={{ searchQuery: "Moskau" }}>

```jsx
<Viewer
  iiifContent="https://clover.iiif.library.northwestern.edu/mocks/content-search/manifest.json"
  searchQuery="Moskau"
/>
```

</ViewerExample>

### From your own part

`clover.search(query)`, from `useClover()`, searches as the field does, and the Root holds
the results as `search`. To ask a service yourself, leaving the Root alone, use
`searchServiceOf(manifest)` and `search(service, query)`.

```jsx
function SearchFor({ query }) {
  const { clover } = Clover.useClover();
  return (
    <button type="button" onClick={() => clover.search(query)}>
      Find {query}
    </button>
  );
}
```

```html twin
<button type="button" id="find">Find Moskau</button>

<script type="module">
  const root = document.querySelector("clover-root");
  document
    .getElementById("find")
    .addEventListener("click", () => root.clover?.search("Moskau"));
</script>
```

### Without highlights

The hits are drawn as the annotation set `SEARCH_SET_ID`. Hide it, and they stay listed.

```jsx
clover.setSetVisible(Clover.SEARCH_SET_ID, false);
```

```html twin
<script type="module">
  // The search's hits are the set "content-search".
  document
    .querySelector("clover-root")
    .clover.setSetVisible("content-search", false);
</script>
```

## Searching supplementing annotations

<div data-code-flavor="both">

Search asks the Manifest's Content Search service for words, and its hits point into the
annotations that hold a page's OCR, drawn where the words are. A Manifest without a
service, as Cookbook 0068's newspaper is, still has its OCR in reach: the Canvas's
annotations menu lists each page's lines in the order given, choosing a line zooms to it,
and the page's toggle draws every line on the image. Clover does not search the lines
itself. They start hidden either way, and the Annotations list leaves them out, as a page
of OCR runs to hundreds of lines; with a service, the menu leaves them to its hits.

Clover treats an annotation as OCR by what it is, not by the file it came in: its
motivation is `supplementing`, its target a region of a Canvas that does not play (a
`xywh` fragment, an SVG selector or a point), and it sits in the Canvas's `annotations`,
embedded or in an AnnotationPage referenced by its address. Its words are a
`TextualBody`, read by its `format`:

- `text/plain`, or any type not listed here: as written.
- `text/html`: IIIF's HTML, sanitized to what the Presentation API allows.
- `text/markdown`: as Markdown.
- No `format`: as written, unless the whole value is HTML (from a first `<` to a last
  `>`), read as IIIF's HTML.

OCR kept in a file of its own is not read line by line:

- `application/xml`, ALTO (its `profile` `http://www.loc.gov/standards/alto/`), or any
  other file given as a Canvas's or the Manifest's `rendering`: offered in Download, as
  Cookbook 0068 offers each page's ALTO.
- `text/plain` (or a `.txt` address), as a Canvas's `rendering` or the body of a
  `supplementing` annotation: shown in full in the Panel's Transcript section.
- `text/vtt`: captions and subtitles of a Canvas that plays, never OCR.

</div>
