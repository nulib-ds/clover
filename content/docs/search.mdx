## API reference

Inside a `Root`, it searches the Manifest through its Content Search service, version 1 or
2, and lists the hits by Canvas, each with the words around it, from up to 10 pages of
results. Choosing a hit goes to it and frames it, and every hit is drawn on the Canvas.
Inside the field, before its clear, Previous and Next step through the hits in order, across Canvases,
showing which is current over the total ("3 / 11"); results go to their first hit as
they arrive, as find in a page does. With `sticky` the field is held in
view as the hits scroll; the Panel's own Search section has it, and draws its hits on the
Canvas only while it is open. The page's own text, its OCR, is not drawn until a
search finds something in it. In a Panel, a search started outside its Search section
opens it ([The open section](/docs/panel#the-open-section)). It renders nothing without a
search service. Its other props, and its `ref`, go to its
element.

<ApiReference elements="clover-search">

| Prop           | Type                 | Default   | Description                                                                            |
| -------------- | -------------------- | --------- | -------------------------------------------------------------------------------------- |
| `headingLevel` | `number`             | `3`       | Each Canvas's heading, one below the heading it sits under.                            |
| `sticky`       | `boolean`            | `false`   | The field held in view as the hits scroll under it.                                    |
| `size`         | `"large" \| "small"` | `"large"` | The field's size: its submit a round control's, or a tad smaller, for a narrow column. |
| `as`           | element type         | `"div"`   | The element to render.                                                                 |
| `className`    | `string`             | —         | Added to `clover-content-search`.                                                      |

</ApiReference>

## Examples

### A query to start with

Use `searchQuery`, on the Viewer or a `Root`, to search as the Manifest opens and again
whenever it changes. The Viewer draws the hits on the Canvas and lists them in its Panel's
Search section.

<ViewerExample resource="search" props={{ searchQuery: "Moskau" }}>

```jsx
<Viewer
  iiifContent="https://nulib-ds.github.io/clover/mocks/content-search/manifest.json"
  searchQuery="Moskau"
/>
```

</ViewerExample>

### From your own part

`clover.search(query)`, from `useClover()`, searches as the field does, and the Root holds
the results as `search`. To ask a service yourself, leaving the Root alone, use
`searchServiceOf(manifest)` and `search(service, query)`.

```jsx
function SearchFor({ query }) {
  const { clover } = Clover.useClover();
  return (
    <button type="button" onClick={() => clover.search(query)}>
      Find {query}
    </button>
  );
}
```

```html twin
<button type="button" id="find">Find Moskau</button>

<script type="module">
  const root = document.querySelector("clover-root");
  document
    .getElementById("find")
    .addEventListener("click", () => root.clover?.search("Moskau"));
</script>
```

### Without highlights

The hits are drawn as the annotation set `SEARCH_SET_ID`. Hide it, and they stay listed.

```jsx
clover.setSetVisible(Clover.SEARCH_SET_ID, false);
```

```html twin
<script type="module">
  // The search's hits are the set "content-search".
  document
    .querySelector("clover-root")
    .clover.setSetVisible("content-search", false);
</script>
```

## Previous versions

[Clover 3.x › Viewer](/docs/3.x/viewer#iiif-content-search)

- `iiifContentSearchQuery={{ q }}` is `searchQuery`.
- `renderOverlays: false` is `clover.setSetVisible(SEARCH_SET_ID, false)`.
- `defaultTab: "manifest-content-search"` is the Panel's `defaultValue="search"`.
- There is no `searchResultsLimit`: every hit returned is listed.
