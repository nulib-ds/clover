## API reference

Place Search inside a `Root`. It searches the Manifest through its Content Search service,
version 1 or 2, and renders nothing when the Manifest has no service.

Search reads up to 10 pages of a response and lists the results by Canvas, with the words
around each one. Choosing a result opens its Canvas and frames the result. Previous and
Next step through the results in order and show the place, such as "3 / 11".

When results arrive, Search selects the first one on the current Canvas, or the first of
all when that Canvas has none. A content state can
[select a specific result](#open-a-content-search-response-to-a-specific-result) instead.

Each result is highlighted on the Canvas. In a `Panel`, results are highlighted only while
its Search section is open, and a search started elsewhere
[opens that section](/docs/panel#the-open-section). `sticky` keeps the field in view while
the results scroll.

OCR stays hidden until a search finds a result in it. When a Manifest has no search
service, the Canvas's annotations menu lists its OCR instead
([Searching supplementing annotations](#searching-supplementing-annotations)).

Its other props, and its `ref`, go to its element.

<ApiReference elements="clover-search">

| Prop           | Type                 | Default   | Description                                                             |
| -------------- | -------------------- | --------- | ----------------------------------------------------------------------- |
| `headingLevel` | `number`             | `3`       | The level of each Canvas's heading: one below the heading above Search. |
| `sticky`       | `boolean`            | `false`   | Keeps the field in view while the results scroll.                       |
| `size`         | `"large" \| "small"` | `"large"` | The field's size. Use `small` for a narrow column.                      |
| `as`           | element type         | `"div"`   | The element to render.                                                  |
| `className`    | `string`             | —         | Added to `clover-content-search`.                                       |

</ApiReference>

## Examples

### Search when the Manifest opens

Set `searchQuery` on the Viewer or a `Root` to search as soon as the Manifest opens, and
again whenever the query changes. The Viewer lists the results in its Panel's Search
section and highlights them on the Canvas. `onSearchChange` reports each new query, and
`""` when the search is cleared, so your page can keep the query in its address.

<ViewerExample resource="search" props={{ searchQuery: "Moskau" }}>

```jsx
<Viewer
  iiifContent="https://clover.iiif.library.northwestern.edu/mocks/content-search/manifest.json"
  searchQuery="Moskau"
/>
```

</ViewerExample>

### Open a Content Search response to a specific result

Pass the query as `searchQuery`. As `iiifContent`, pass a
[content state](/docs/content-state#target-a-content-search-result) whose target is one
result's annotation. That annotation must match an annotation in the search responses:
Clover runs the search and compares their `id` values.

- If a response has an annotation with the same `id`, Clover selects that result.
- If none does, Clover shows the content state's annotation in
  [Annotations](/docs/annotations) instead, as it would any annotation. The search still
  selects its first result on that Canvas, or its first result of all when that Canvas has
  none.
- If the search finds nothing, the annotation stays selected in Annotations.

This example selects the tenth of ten results for "pedals", on Page 21.

### Search from your own component

Call `clover.search(query)`, from `useClover()`, to search as the field does. The `Root`
keeps the results in its state as `search`. To query a service without the `Root`, use
`searchServiceOf(manifest)` and `search(service, query)`.

```jsx
function SearchFor({ query }) {
  const { clover } = Clover.useClover();
  return (
    <button type="button" onClick={() => clover.search(query)}>
      Find {query}
    </button>
  );
}
```

```html twin
<button type="button" id="find">Find Moskau</button>

<script type="module">
  const root = document.querySelector("clover-root");
  document
    .getElementById("find")
    .addEventListener("click", () => root.clover?.search("Moskau"));
</script>
```

### Hide the highlights on the Canvas

Search highlights its results on the Canvas as the annotation set `SEARCH_SET_ID`. Hide
that set, and the results stay listed.

```jsx
clover.setSetVisible(Clover.SEARCH_SET_ID, false);
```

```html twin
<script type="module">
  // The search's results are the set "content-search".
  document
    .querySelector("clover-root")
    .clover.setSetVisible("content-search", false);
</script>
```

## Searching supplementing annotations

<div data-code-flavor="both">

A Content Search service finds words in a Manifest's OCR, and each result points to the
annotation that holds them. Clover doesn't search OCR itself.

For a Manifest without a service, such as Cookbook 0068's newspaper, the Canvas's
annotations menu lists each page's lines. Choose a line to zoom to it, or turn on the
page's toggle to show every line on the image. With a service, the menu leaves OCR out,
and search results show it.

OCR starts hidden either way, and the Annotations list leaves it out, since one page can
hold hundreds of lines.

Clover treats an annotation as OCR when:

- Its motivation is `supplementing`.
- Its target is a region of a Canvas that has no duration: an `xywh` fragment, an SVG
  selector or a point.
- It is in the Canvas's `annotations`, embedded or in a referenced AnnotationPage.

Its text is a `TextualBody`, read by its `format`:

- `text/plain`, or any type not listed here: as written.
- `text/html`: IIIF's HTML, sanitized to what the Presentation API allows.
- `text/markdown`: as Markdown.
- No `format`: as written, unless the whole value is HTML (from a first `<` to a last
  `>`), read as IIIF's HTML.

OCR in a separate file isn't read line by line:

- `application/xml`, ALTO (its `profile` `http://www.loc.gov/standards/alto/`), or any
  other file given as a Canvas's or the Manifest's `rendering`: offered in Download, as
  Cookbook 0068 offers each page's ALTO.
- `text/plain` (or a `.txt` address), as a Canvas's `rendering` or the body of a
  `supplementing` annotation: shown in full in the Panel's Transcript section.
- `text/vtt`: captions and subtitles of a Canvas that plays, never OCR.

</div>
