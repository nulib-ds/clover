# Mocks

<div className="docs-lede">
  IIIF resources Clover publishes for testing a viewer against: complete, valid,
  and stable at their URLs. Each is generated from one source in `docs/mocks/`,
  so the published files, the live service in `npm run dev`, and the docs' own
  demos always agree.
</div>

Use them from any viewer, test suite or prototype. Publish a new mock the same way when
it is complex enough to reuse: a generator in `docs/mocks/<name>/`, its files written to
`public/mocks/<name>/` by `npm run build:mocks`, and a section on this page.

## Content Search 2.0: a newspaper issue

Two pages of the _Berliner Tageblatt_ of February 16, 1925, with their OCR and a IIIF
Content Search 2.0 service. The OCR is the newspaper's own (Fraktur, errors included),
with a position for every word, so search hits and text land where the print is.

| Resource        | Published (static)                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Manifest        | [`/mocks/content-search/manifest.json`](https://clover.iiif.library.northwestern.edu/mocks/content-search/manifest.json)                                                 |
| OCR, by line    | [`/mocks/content-search/ocr/p1-lines.json`](https://clover.iiif.library.northwestern.edu/mocks/content-search/ocr/p1-lines.json), `p2-lines.json`                        |
| OCR, by word    | [`/mocks/content-search/ocr/p1-words.json`](https://clover.iiif.library.northwestern.edu/mocks/content-search/ocr/p1-words.json), `p2-words.json`                        |
| Example answers | [`/mocks/content-search/search/examples/nicht.json`](https://clover.iiif.library.northwestern.edu/mocks/content-search/search/examples/nicht.json) and others: see below |
| Search service  | `/mocks/content-search/search`: answered live by `npm run dev` or `mockFetch`, not by the static site                                                                    |

All under `https://clover.iiif.library.northwestern.edu`.

### What is in it

- **The Manifest** has two Canvases (3602 × 5000 and 3536 × 4999), drawn from the IIIF
  Image API reference server, and a `SearchService2`. Each Canvas references its OCR by
  line in `annotations`.
- **OCR pages** are AnnotationPages of `supplementing` annotations with a `TextualBody`
  (`language: "de"`) targeting the region it was read from, `canvas#xywh=x,y,w,h`, in the
  Canvas's pixels. Each carries a [`textGranularity`](https://iiif.io/api/extension/text-granularity/)
  of `line` (about 310 a page) or `word` (about 2,500 a page). The Manifest references
  only the lines; the words are there for testing word-level highlighting.
- **Search answers** follow Content Search 2.0:
  - `items` are `highlighting` annotations on each match's OCR box, a SpecificResource
    on the Canvas (with `partOf` naming the Manifest) and an `xywh=` FragmentSelector.
  - `annotations` holds a page of `contextualizing` annotations, one per hit, quoting it
    with a `TextQuoteSelector`: `prefix`, `exact` and `suffix`, six words either side.
  - Results come 25 to a page, in an AnnotationCollection (`partOf` with `total`,
    `first` and `last`), with `startIndex`, `prev` and `next`.
- **Matching** ignores case, accents and punctuation, and reads the Fraktur long s (ſ) as
  s. A word matches if it contains the query, so `berlin` finds "Berliner"; a phrase
  matches consecutive words, its box the union of theirs.

### Example answers

Static files, for tests that need a fixed answer. Each is exactly what the live service
returns for the query, except that page links point at the next file.

| ------------- | ---- | ---------------------------------------- |
| `nicht`       | 36   | `nicht.json`, `nicht-2.json` (two pages) |
| `moskau`      | 11   | `moskau.json`                            |
| `drei jungen` | 4    | `drei-jungen.json` (a phrase)            |
| `zzzz`        | 0    | `zzzz.json` (no results)                 |

### Searching it live

A static site cannot read `?q=`, so the published search service URL answers nothing by
itself. Two ways to search any query:

- **`npm run dev`** serves a live copy of the whole mock, with every id under the dev
  server: `http://localhost:3000/api/mocks/content-search/manifest.json`. Its service
  answers any `q` and `page`, with `Access-Control-Allow-Origin: *` so a viewer on
  another port can use it.

  ```sh
  curl "http://localhost:3000/api/mocks/content-search/search?q=moskau"
  ```

- **`mockFetch`**, from the generator, is a `fetch` that answers the published mock's
  URLs in the browser and passes everything else on. Hand it to anything that takes a
  `fetch`. The [Viewer's Content Search demo](/docs/viewer#content-search) does:

  ```jsx
  import { mockFetch } from "docs/mocks/content-search/index.mjs";

  <Clover.Viewer
    iiifContent="https://clover.iiif.library.northwestern.edu/mocks/content-search/manifest.json"
    request={{ fetch: mockFetch() }}
  />;
  ```

  ```html twin
  <script type="module">
    import { mockFetch } from "docs/mocks/content-search/index.mjs";

    document.querySelector("clover-viewer").request = { fetch: mockFetch() };
  </script>

  <clover-viewer
    iiif-content="https://clover.iiif.library.northwestern.edu/mocks/content-search/manifest.json"
  ></clover-viewer>
  ```

<Callout type="info">
  Clover 3.x's older newspaper mock (`/manifest/content-search/`) is unchanged.
  Its live service, `/api/fixtures/content-search/1`, works in `npm run dev`
  again: the docs build is a static export, and the export setting used to turn
  API routes off in development too.
</Callout>

### Changing it

The generator is `docs/mocks/content-search/index.mjs`; the OCR is
`docs/mocks/content-search/ocr.json` (words in reading order, `[text, x, y, w, h]`).
After changing either, run `npm run build:mocks` and commit `public/mocks/`. The OCR
pages are written compact, and Prettier leaves `public/mocks/` alone.

## Hindenburg: a broadcast and its box

Northwestern University Libraries' record of WLS-AM's broadcast of Herbert Morrison and
Charlie Nehlsen's recording of the Hindenburg disaster (May 1937), from the Charles
Deering McCormick Library of Special Collections: a Manifest of a Canvas of sound, the
reel's, then four photographs, the front and back of the reel's enclosure and of its
carrier, with:

- an `accompanyingCanvas` on the Canvas of sound, which the record does not carry: the
  enclosure's back, the box the reel came in, where its label is written (the one the
  record's Notes quote), painted with the record's own image of it, so a player shows the box while the
  broadcast plays;
- no `width` and `height` on the Canvas of sound and its sound, and no `duration` on the
  photographs: the API gives them stand-ins (100 × 100, and 1 second), which sound and
  stills do not have, so the Canvas of sound is a Timeline once upgraded to
  Presentation 4;
- English captions, a `supplementing` WebVTT file (`captions.vtt`). The record has no
  transcript, so the words were transcribed from the broadcast by speech recognition
  (Whisper) and corrected by hand: the names from the record and the broadcast itself
  (Herbert Morrison, Charles Nehlsen, WLS, the Prairie Farmer station, Lakehurst), and
  those of the airship's commanders and survivors as history gives them. A word that
  could not be told is `[unclear]`, and so is a passenger's answer (10:25–10:54). They
  have not yet been checked word for word by a listener;
- nine chapters (`structures`), one for each part of the broadcast (the studio's
  introduction, Morrison asked about the scene, the landing, the fire, his return to
  the wreck, the survivors he meets, the count of the saved, the studio's close), each
  titled with the broadcast's own words where it begins: "It burst into flames!";
- a page of annotations, "The broadcast", eight `describing` notes, each on a stretch of
  the sound (`t=start,end`) and saying what happens there;
- everything else as Northwestern's Digital Collections API published it on October 24,
  2026, apart from the ids of the Manifest and its Canvases, which are the mock's own;
- the sound from Northwestern's HLS stream (14 minutes), and the images from its IIIF
  Image API (level 2, CORS open).

| Resource | Published (static)                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| Manifest | [`/mocks/hindenburg/manifest.json`](https://clover.iiif.library.northwestern.edu/mocks/hindenburg/manifest.json) |
| Captions | [`/mocks/hindenburg/captions.vtt`](https://clover.iiif.library.northwestern.edu/mocks/hindenburg/captions.vtt)   |

## Paged: a catalog in spreads

Northwestern University Libraries' record of the White Sewing Machine Company's
_Portfolio of illustrations showing the White bicycles : then and now_ (1896), a `paged`
Manifest of 31 Canvases (its covers and 29 pages), with:

- a `summary`, which the record has none of, written from its own fields (Publisher,
  Location, Date, the illustrators its Alternate Title names, Materials) and its pages,
  in under 30 words: "The White Sewing Machine Company of Cleveland issued this bicycle
  catalog in 1896. Color plates by Thulstrup, Mente, Veenfliet, and Clarke pair “Then”
  with “Now”; specifications describe four models.";
- `behavior: ["facing-pages"]` on Page 15. It is one image of a whole opening, a color
  plate across both pages (9423 × 4694, twice a page's width), so it is shown alone and
  the pages after it pair as the book's openings do. The spreads run Front Cover, 1–2 …
  13–14, 15, 16–17 … 28–29, Back Cover. As published, the plate pairs with Page 16, and
  every opening after it is split;
- `structures`, which the record has none of: a Range for each of the catalog's sections,
  titled exactly as the catalog has it, by the heading printed on its page (its words,
  without the closing period), or, for a cover, by the Canvas's own label. Front Cover;
  Introduction; Specifications “White” 1896 Model A, B, C and D, each with its engraving;
  “White” Bearings (Crank Bearing, The Hubs); Important Features of the “White”, six
  headings, where those that share a page each name their region of it (`#xywh=`);
  Guaranty on “White” Bicycles; Tire Guarantees; Terms of Sale; Back Cover;
- on each plate that pairs a "Then" with a "Now" (Pages 4, 6, 18, 20, 22, 24 and 26, and
  the Back Cover), the two tagged where they are, as
  [Cookbook recipe 0021](https://iiif.io/api/cookbook/recipe/0021-tagging/) tags a
  fountain: "Then" around the inset scene and the word printed by it, "Now" around most of
  the picture, clear of its edges (on the Back Cover, the round scene below), each after
  the printed word described briefly, as a cataloger would ("Now – Postman on bicycle
  greets woman in period style white dress on bicycle."). Page 15 prints "Now" with no
  "Then", so it has none;
- its words, read by machine with Apple's Vision framework and not corrected by hand
  (`docs/mocks/paged/ocr.json`): each page's OCR by line and by word, `supplementing`
  text on the region each was read from, with a `textGranularity`, the lines referenced
  from each Canvas that has words ("OCR (lines)"). Running text reads well; ornamental
  lettering (the covers' script, a plate's signature) and some fractions do not;
- a IIIF Content Search 2.0 service (`SearchService2`), searchable by word or phrase, as
  the newspaper's is: each hit a `highlighting` annotation on its words' box, with the
  words around it, 25 to a page of results;
- everything else as Northwestern's Digital Collections API published it on 14 October
  2026, apart from the ids of the Manifest and its Canvases, which are the mock's own;
- the images from Northwestern's IIIF Image API (level 2, CORS open).

## Rudolf Hess at Nuremberg: people followed through a film

_Sentencing of Nazi Leaders at Nuremberg_, a reel of the International Military
Tribunal's judgment from the US National Archives (National Archives Identifier 23769,
local identifier 111-ADC-10005), as
[Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Sentencing_of_Nazi_Leaders_at_Nuremberg.webm)
publishes it, made to show Rudolf Hess's distress in the dock beside the other defendants:
Hess is marked wherever he is in view, and so are the defendants around him at that end
of the dock, wherever each can be told: Hermann Göring and Joachim von Ribbentrop either
side of him and Wilhelm Keitel beyond Ribbentrop, in the front row, and Erich Raeder,
Baldur von Schirach and Fritz Sauckel in the row behind. Commons is not a
IIIF publisher, so the Manifest is the mock's own, made from the file's Commons record
(read on October 19, 2026):

- **The Manifest** (Presentation 3) is labeled "Rudolf Hess at Nuremberg Sentencing" (its dates are in its metadata), and its summary says what it shows of him. Its
  metadata are the record's: the National Archives' title (the reel's, which the Canvas
  keeps as its label) and description among them. Its rights are the public domain, the
  film being the US Army Signal Corps'. Its homepages are the Commons page and the
  National Archives Catalog's record.
- **Its date** is the two days of the judgment the film shows, as its `navDate` (30
  September 1946) and a Date line. The Commons record's only date is 1947-10, a year
  after the trial, so the days are read from the film against the trial's record
  ([30 September](https://avalon.law.yale.edu/imt/09-30-46.asp),
  [1 October](https://avalon.law.yale.edu/imt/10-01-46.asp)). The soundtrack carries the
  reading of 30 September up to its last words, on the SS and the General Staff, and the
  Tribunal adjourning "until 1 October 1946 at 0930 hours" (5:21); from 5:46 it carries
  the verdicts of 1 October, over the courtroom and then the dock. Hess is taken ill and
  led out of the dock on 30 September, during the reading on the murder and
  ill-treatment of the civilian population, if the film's sound was recorded with its
  pictures (the record does not say when). Despite its title, the reel shows no
  sentencing: the sentences were pronounced on the afternoon of 1 October.
- **Its one Canvas** is 654 × 480 and 671.164 s, the film as shown (stored 720 × 480, at a
  display aspect of 654:480). It paints the original WebM file (VP8 and Vorbis, 133 MB),
  and its `placeholderCanvas` is the still Commons cuts from the file at 14 s (500 × 367,
  Commons cuts stills at its own widths only).
- **Two AnnotationPages.** "Rudolf Hess" holds three annotations, one for each part of
  what the film shows of him, each `identifying` and `describing`: "Hess shows
  distress" (0:12–1:25), "Hess is led out of the dock" (1:25–1:40) and "Hess returns to
  the dock" (3:18 to the end). "Other Defendants" holds an `identifying` annotation for
  each of the others followed, named by him, in the dock's order: Göring, Ribbentrop and
  Keitel, then Raeder, Schirach and Sauckel. Each was told by his face, against a
  photograph of the dock, and by where he sat. Karl Dönitz, who sat behind Göring, is not
  marked: the close shots leave him out of frame, and in the wide shot from 1:25.7 and the
  pan from 3:18 the back row is too small and soft to tell one man from another, so none
  of the back row is marked there (nor Keitel in the wide shot). Nor is Keitel in the
  close shot from 0:45, where only half his face is in frame and the man behind him is
  hard to tell from him.
- **Its English captions**, a `supplementing` WebVTT file (`captions.vtt`, 99 cues), as
  [Cookbook recipe 0219](https://iiif.io/api/cookbook/recipe/0219-using-caption-file/)
  gives one. The soundtrack is the courtroom's interpretation system, which cuts between
  its channels, so the captions follow: the judgment read in English, in the published
  judgment's words, checked against the soundtrack (where the record's two printings
  differ, as on Göring's "16th July, 1941" and "desettling", the one the soundtrack
  agrees with); the Russian interpretation (1:57–3:16, the euthanasia killings,
  Bach-Zelewski's testimony and the persecution of the Jews; 7:02–7:25, the end of the
  verdict on Hess) and the French (9:17–9:40, the end of Keitel's) in the record's
  English, marked "[In Russian]" or "[In French]"; and a voice over the sound system
  between the days ("Hello, sound recording…"), as heard. An ellipsis marks speech cut
  by the film's editing. The soundtrack was transcribed with Whisper (`small` and
  `medium.en`) only to place and check the words; none of its own words are used where
  the record has them.
- **Its transcript**, the same words as plain text (`transcript.txt`), the Canvas's
  `rendering`, as
  [Cookbook recipe 0017](https://iiif.io/api/cookbook/recipe/0017-transcription-av/)
  gives one, labeled "Transcript in plain text format" (recipe 0253's words for a
  film's). It has a paragraph for each stretch of the reading the film keeps whole: one
  starts after a pause, at a cut, where the voice or language changes, and where the
  editing cuts the speech. Each paragraph of a stretch in Russian or French opens with its
  note, which the captions give once.
- **Chapters**, a Range for each part of the film the National Archives' description
  names, titled with its words (each cut to the clause that names the shot) and timed
  to the film's cuts: "Sitting in prisoners' dock listening to testimony" (0:12.5),
  "Hess taken ill leaves prisoners' dock" (1:25.6), "Shots of English and US prosecution
  tables" (1:57.2), "Scenes of Justice Kravechenko, Russian Justice, reading statement
  from bench" (2:38.1), "Pan of prisoners' dock and courtroom" (3:17.8), "Court

The regions were found with OpenCV's CSRT tracker on Commons' 480p transcode (the same
654 × 480 frame), each shot begun from a region placed by eye, each box kept at its size,
and the tracker's movement held to regions read by eye where it wandered: every 2.5 s
for Hess in the close shot from 0:45, where its boxes grew onto Ribbentrop, and every few
seconds for Göring from 6:28, when a man walking past the camera threw it. For Hess in
the wide shot, where it lost him as he stood, the regions were read by eye every half
second; Ribbentrop there was followed from the frame Hess uncovers him, checked every
quarter second as Hess passes him again on his way out. The others were followed the
same way, each stretch ending where he leaves the frame or the tracker could no longer
hold him; where it lost Schirach and Sauckel as the officer leans across the dock
(0:32–0:35), their regions were read by eye. The regions were then thinned to
the fewest stretches that keep within 3 px of every frame, and each shot's frames were
checked with its regions drawn on them. They are as good as the film allows, which is
soft and dark: about a head's width either way.
