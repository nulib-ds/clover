## API reference

Inside a `Root`, it lists the `rendering` of the Canvases in view, under "This page", and
of the Manifest, under "All pages", as links, each with its format. Pressed, a link saves
its file rather than opening it, where its server lets the file be fetched, and opens it
in a new tab where not. With neither, it renders nothing. Its other props go to the `div` around its groups; it takes no `as` or
`ref`.

<ApiReference elements="clover-download">

| Prop           | Type     | Default | Description                                             |
| -------------- | -------- | ------- | ------------------------------------------------------- |
| `headingLevel` | `number` | `3`     | The groups' headings: one below the heading above them. |
| `className`    | `string` | —       | Added to `clover-download`.                             |

</ApiReference>

## Examples

### Heading level

Use `headingLevel` for its groups' headings, "This page" and "All pages": the level below
the heading it sits under, here `4` under an `h3`.

<Example>
<PartDemo
  part="Download"
  resource="page-transcript"
  body
  props={{ headingLevel: 4 }}
/>

```jsx
<Clover.Download headingLevel={4} />
```

</Example>

### In the templates

`Document` puts its links in its toolbar, and `Default` lists them from a Download button
beside its Panel's About heading. In either, `download={false}` leaves them out.

<ViewerExample
  resource="https://clover.iiif.library.northwestern.edu/mocks/page-transcript/manifest.json"
  template="Document"
>

```jsx
<Viewer
  iiifContent="https://clover.iiif.library.northwestern.edu/mocks/page-transcript/manifest.json"
  template={Document}
/>
```

</ViewerExample>

### One resource's rendering

For one resource's `rendering` alone, as a plain list of links, use
[`Rendering`](/docs/primitives/rendering).
