# Rendering

<Callout type="info">
  Looking for the Rendering of Clover 3.x, `@samvera/clover-iiif`? It is at
  [Clover 3.x › Rendering](/docs/3.x/rendering).
</Callout>

Other formats of the object, such as a PDF of the whole of it or a Canvas's transcript as
text, from its [`rendering`](https://iiif.io/api/presentation/3.0/#rendering), as a list
of links. Inside a `Root` it reads the Root's Manifest, or the current Canvas with
`of="canvas"`, which changes as the reader moves. A `value` you pass wins, so it works
outside a `Root` too.

```jsx
import * as Clover from "@nulib/clover";

<Clover.Root iiifContent={manifestUrl}>
  <Clover.Content />
  <Clover.Rendering of="canvas" />
</Clover.Root>;
```

Below, _Lunchroom Manners_ from Clover's [mocks](/docs/mocks), whose Canvas gives the
film's transcript as plain text, read with `of="canvas"`.

<PartDemo part="Rendering" resource="transcripts" props={{ of: "canvas" }} />

Outside a `Root`, pass the property as IIIF gives it, one resource or a list:

```jsx
<Clover.Rendering
  value={[
    {
      id: "https://example.org/catalog.pdf",
      type: "Text",
      label: { en: ["PDF"] },
      format: "application/pdf",
    },
  ]}
/>
```

## Links

Each resource is a link to its `id`, named by its `label` as plain text, in the reader's
language: the Root's `language`, else the page's, else the browser's. The link carries
the label's `lang`; a label in `none` carries none, and takes the page's. A resource with
no label is named by its address. Its `format` follows the link, in parentheses and
outside it, so the link's name is the label alone. Of each resource, only its `id`,
`label` and `format` are read. One with no `id` is left out, and with none to show,
`Rendering` renders nothing.

The list is a `ul`, a link to each `li`. With Clover's stylesheet, each `li` is at least
24px tall, so the links' centers are 24px apart at any type size (WCAG 2.5.8).

About does not show `Rendering`. Its Download section lists the `rendering` of the
Canvases in view and of the Manifest, as [`Download`](/docs/download) does behind its button. `Rendering`
is one resource's, as a plain list, for a layout of your own.

## Props

| Prop    | Type                     | Description                                                          |
| ------- | ------------------------ | -------------------------------------------------------------------- |
| `of`    | `"manifest" \| "canvas"` | Whose `rendering`: the Manifest's (default) or the current Canvas's. |
| `value` | resource or list         | `{ id, label, format }`, shown in place of the Root's.               |

Its other props (`id`, `className`, `style`, `aria-*`) go to the `ul`. It takes no `as`
and no `lang`: it is always a list, and each link carries its label's language.

### Styles

`.clover-rendering` is the list, and `.clover-link-format` each format, in
`--clover-color-primary-muted` at `--clover-text-s`. Clover leaves the list's markers to
your page.

## From Clover 3.x

Import it from `@nulib/clover`, as `Clover.Rendering` or by name.

| 3.x `Rendering`                                   | Clover 4                                         |
| ------------------------------------------------- | ------------------------------------------------ |
| `rendering`                                       | `value`; inside a `Root`, read from the Manifest |
| `as` (`ul` or `ol`)                               | Not taken: always a `ul`                         |
| `className`, `style`, `title`, `data-*`, `aria-*` | The same, on the `ul`                            |
| `lang`                                            | Not taken: each link carries its label's         |
| No format shown                                   | Each resource's `format` follows its link        |
