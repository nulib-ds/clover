# Primitives

Each IIIF descriptive property is a part of its own. Inside a `Root`, each reads the
Manifest, or with `of="canvas"` the Canvas the reader is on. A value you pass as `value`
wins (`label`, for `Label`), so each works outside a `Root` too. A part whose property is
absent renders nothing.

```jsx
import * as Clover from "@nulib/clover";
import "@nulib/clover/styles.css";

<Clover.Root iiifContent={manifestUrl}>
  <Clover.Content />
  <Clover.Label as="h2" />
  <Clover.Summary />
  <Clover.Metadata />
  <Clover.RequiredStatement />
  <Clover.Rights />
</Clover.Root>;
```

## The parts

| Part                                                       | What it shows                                                          |
| ---------------------------------------------------------- | ---------------------------------------------------------------------- |
| [`Label`](/docs/primitives/label)                          | `label`, as text, in the element you choose                            |
| [`Thumbnail`](/docs/primitives/thumbnail)                  | `thumbnail`, or a Canvas's first image, as an `img` named by its label |
| [`Summary`](/docs/primitives/summary)                      | `summary`, cut to five lines with "Read more"                          |
| [`Metadata`](/docs/primitives/metadata)                    | `metadata`, as a description list of labels and values                 |
| [`RequiredStatement`](/docs/primitives/required-statement) | `requiredStatement`, the text that must be shown with the resource     |
| [`Rights`](/docs/primitives/rights)                        | `rights`, as a link to the license or rights statement                 |
| [`Homepage`](/docs/primitives/homepage)                    | `homepage`, the resource's own web page, as links                      |
| [`SeeAlso`](/docs/primitives/see-also)                     | `seeAlso`, machine-readable descriptions elsewhere, as links           |
| [`Rendering`](/docs/primitives/rendering)                  | `rendering`, other formats of the resource (a PDF, say), as links      |
| [`PartOf`](/docs/primitives/part-of)                       | `partOf`, the Collections the resource belongs to, as links            |
| [`Id`](/docs/primitives/id)                                | `id`, as a link to the resource's IIIF JSON                            |
| [`Value`](/docs/primitives/value)                          | Any IIIF language map you hold, read by its `format`                   |

`Homepage`, `SeeAlso`, `Rendering` and `PartOf` list each resource by its label (its `id`
where it has none), with its format.

## In a Root, or on its own

Inside a `Root`, a part reads the Root's resource wherever it sits in your markup. With
`of="canvas"` it reads the Canvas the reader is on, and changes as they move. On its own,
it shows what you give it:

```jsx
<Clover.Label label={{ en: ["A letter"] }} as="h2" />
<Clover.Summary value={{ en: ["Written in 1849."] }} />
<Clover.Rights value="http://rightsstatements.org/vocab/InC/1.0/" />
```

`Thumbnail` takes the resource to picture as its `value` (a Manifest, a Canvas or a
Collection), not its `thumbnail`. `Value` has no `of`: it shows only the value it is given.

## Languages

Text is read in the Root's `language`, else the page's `<html lang>`, else the browser's
languages: the closest language the value has (`fr` for a reader in `fr-CA`), else its
`none`, else the first it has. A language's several values are joined with commas.

Each element carries the language its text is in as `lang`, so assistive technology reads
it in that language (WCAG 3.1.2). Text in `none` carries no `lang`, and takes the page's.
Clover sets each `lang` itself.

## HTML

IIIF allows a little HTML in its values. A value is HTML when it runs from a first `<` to a
last `>`, as IIIF's rule has it; any other value is shown as written, tags and all, its
line breaks kept. `Summary`, the values of `Metadata` and `RequiredStatement`, and `Value`
show HTML. `Label`, a link's label and a thumbnail's `alt` are plain text: tags are
dropped, and entities such as `&amp;` decoded.

HTML shows as plain text at first, then as HTML once the sanitizer arrives, limited to what
the Presentation API allows: `a`, `b`, `br`, `i`, `img`, `p`, `small`, `span`, `sub` and
`sup`, with links to `http:`, `https:` and `mailto:` addresses only. Scripts, event
handlers, `style`, `aria-*` and `data-*` attributes are removed, and so are `javascript:`
and `data:` addresses. `lang` and `dir` are kept, so a value can mark a phrase in another
language or direction. The sanitizer, DOMPurify (about 9 kB gzip), loads only when a value
carries markup, so a page whose values are plain never fetches it.

## Styles

Each part names itself with one class on its element, and `className` adds your own:
`.clover-label`, `.clover-thumbnail`, `.clover-summary`, `.clover-metadata`,
`.clover-required-statement`, `.clover-rights`, `.clover-homepage`, `.clover-see-also`,
`.clover-rendering`, `.clover-part-of`, `.clover-id` and `.clover-value`. Their other props
(`id`, `style`, `aria-*`) go to that element.

In `Summary`, `Metadata` and `RequiredStatement`, Clover's stylesheet underlines the links
in IIIF's HTML, not only colors them, since a page's reset may take the browser's
underline away; and long unbroken values (an address, a file name) wrap, rather than push
the layout sideways.
