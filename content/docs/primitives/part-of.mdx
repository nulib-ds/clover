# PartOf

<Callout type="info">
  Looking for the PartOf of Clover 3.x, `@samvera/clover-iiif`? It is at [Clover
  3.x › PartOf](/docs/3.x/partOf).
</Callout>

What the object is part of, from its
[`partOf`](https://iiif.io/api/presentation/3.0/#partof), as a list of links: for a
Manifest, the Collections it belongs to. Inside a `Root` it reads the Root's Manifest, or
the current Canvas with `of="canvas"`. A `value` you pass wins, so it works outside a
`Root` too.

```jsx
import * as Clover from "@nulib/clover";

<Clover.Root iiifContent={manifestUrl}>
  <Clover.PartOf />
</Clover.Root>;
```

Below, the White Sewing Machine Company's 1896 bicycle catalog from Clover's
[mocks](/docs/mocks), part of one Collection at Northwestern University Libraries, of
bicycle and bicycle parts catalogs.

<PartDemo part="PartOf" />

Outside a `Root`, pass the property as IIIF gives it, one resource or a list:

```jsx
<Clover.PartOf
  value={[
    {
      id: "https://example.org/collection.json",
      type: "Collection",
      label: { en: ["Bicycle catalogs"] },
    },
  ]}
/>
```

## Links

Each resource is a link to its `id`, named by its `label` as plain text, in the reader's
language: the Root's `language`, else the page's, else the browser's. The link carries
the label's `lang`; a label in `none` carries none, and takes the page's. A resource with
no label is named by its address, and one with a `format` has it after the link, in
parentheses and outside it. Of each resource, only its `id`, `label` and `format` are
read, so a `summary` given in `partOf` is not shown. One with no `id` is left out, and
with none to show, `PartOf` renders nothing.

A Collection's `id` is the address of its IIIF JSON, so each link opens the JSON, not a
web page. To show the Collection itself, its label, summary and members, use the Panel's
[Collection section](/docs/panel#sections), the `Collection` part, which fetches the
Collection when it first shows.

The list is a `ul`, a link to each `li`. With Clover's stylesheet, each `li` is at least
24px tall, so the links' centers are 24px apart at any type size (WCAG 2.5.8).

## Props

| Prop    | Type                     | Description                                                       |
| ------- | ------------------------ | ----------------------------------------------------------------- |
| `of`    | `"manifest" \| "canvas"` | Whose `partOf`: the Manifest's (default) or the current Canvas's. |
| `value` | resource or list         | `{ id, label, format }`, shown in place of the Root's.            |

Its other props (`id`, `className`, `style`, `aria-*`) go to the `ul`. It takes no `as`
and no `lang`: it is always a list, and each link carries its label's language.

### Styles

`.clover-part-of` is the list, and `.clover-link-format` each format, in
`--clover-color-primary-muted` at `--clover-text-s`. Clover leaves the list's markers to
your page.

## From Clover 3.x

Import it from `@nulib/clover`, as `Clover.PartOf` or by name.

| 3.x `PartOf`                                      | Clover 4                                         |
| ------------------------------------------------- | ------------------------------------------------ |
| `partOf`                                          | `value`; inside a `Root`, read from the Manifest |
| `as` (`ul` or `ol`)                               | Not taken: always a `ul`                         |
| `className`, `style`, `title`, `data-*`, `aria-*` | The same, on the `ul`                            |
| `lang`                                            | Not taken: each link carries its label's         |
