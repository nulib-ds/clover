# i18n

<div className="docs-lede">
  Clover translates its interface language: its control labels ("Zoom in"),
  section titles ("About") and announcements ("Item 2 of 17"). IIIF text (a
  label, a summary, metadata) is in the resource's own languages, and Clover
  chooses among them too.
</div>

Clover has its own translator, well under 1 kB gzipped, with no translation library to
install. Its strings are kept the way i18next keeps them, so `initCloverI18n` calls from
Clover 3.x keep working.

## Languages Clover ships

Each is complete: it has every string English has, which a test checks.

| Language            | Tag       | Notes                                                                                                               |
| :------------------ | :-------- | :------------------------------------------------------------------------------------------------------------------ |
| English             | `en`      | Clover's default. Clover defers to the visitor's languages, and to the languages you configure, where they are set. |
| Spanish             | `es`      |                                                                                                                     |
| Finnish             | `fi`      |                                                                                                                     |
| French              | `fr`      |                                                                                                                     |
| Japanese            | `ja`      |                                                                                                                     |
| Norwegian Bokmål    | `nb`      |                                                                                                                     |
| Norwegian Nynorsk   | `nn`      |                                                                                                                     |
| Norwegian           | `no`      | The same strings as `nb`.                                                                                           |
| Portuguese          | `pt`      | European Portuguese, which Brazilian (`pt-BR`) gets too.                                                            |
| Simplified Chinese  | `zh-Hans` | What `zh`, `zh-CN` and `zh-SG` get.                                                                                 |
| Traditional Chinese | `zh-Hant` | What `zh-TW` and `zh-HK` get.                                                                                       |

Check the languages a site would offer, as `initCloverI18n({ languages })` sets them. With
none checked, Clover speaks your language, from your browser, or English where it has none
of yours. Each resource here comes in several languages, which About's toggle offers,
after a globe; check others, and it offers those too. Open one of your own by its address
or a content state. The code under the Viewer is what draws it as
checked. This page is in English, so each of the interface's words in another language
carries that language's `lang`.

## How Clover chooses

Clover chooses its interface language first, then the resource's, and About's heading
offers both as one toggle.

### Clover's interface language

1. It takes the languages your site offers, set with `initCloverI18n({ languages })`.
   The page's `<html lang>` is always among them; where it declares none and none are
   set, English.
2. It reads the visitor's languages, which the browser takes from the operating system.
3. It speaks the visitor's first language that it has strings for. When it has none of
   them, it speaks your first language.
4. Where the visitor's language differs from yours, About's toggle offers both, so the
   visitor can switch. The choice is the page's: every Clover on it follows. It lasts
   the visit, and Clover stores nothing.

So a Japanese visitor to an English site sees Japanese, and may choose English. A German
visitor sees English, as Clover ships no German, and is offered nothing.

A tag tries its language in its script, then its base language, so `pt-BR` gets `pt`,
`zh-TW` Traditional Chinese (`zh-Hant`), and `zh-CN` Simplified (`zh-Hans`). For a string
a language lacks, Clover uses the `fallbackLng` you give, then your languages, then
English.

### The resource's languages

1. Clover counts the languages in what the resource says of itself.
2. Where there are two or more, About's toggle offers them, whatever your site offers.
3. Each value shows in the visitor's language, then in the interface language, then in
   yours. A value in none of them shows in its first language.

So a Japanese visitor sees a resource's Japanese values, and the German visitor its
German ones, though the interface is English.

### One toggle

Every choice of languages in Clover is one construct: a globe, then the languages' codes.
About's offers the languages the resource describes itself in, then the interface
languages it has none of, each once: `zh-CN` stands for Simplified Chinese. Choosing a
language the resource has shows it in that language, and speaks it too where Clover has
strings for it, so choosing `ES` turns the interface Spanish. Choosing a language only
your site offers changes the interface alone. As soon as its codes would reach About's
title, the toggle folds into the globe, the code in use and a caret, which opens them;
elsewhere it folds past five. A language chosen for a resource goes with it when another
opens, the interface back to the visitor's.

A choice that changes only one section stays in it. An annotation set whose languages
About's toggle does not offer, Maktaba's manuscript's Arabic and English, say, offers its
own, the same toggle, in its header, and its choice is the set's alone. A Transcript
does the same with its caption files. A Transcript with a plain-text transcript among its
files ("TXT") always offers its own choice, of files rather than languages, without the
globe.

<span data-code-flavor="both">`interfaceLanguages={false}`</span> on the Viewer,
`Panel` or `About` leaves the interface languages out of it, and
<span data-code-flavor="both">`languages={false}`</span> the resource's.

## Configuring the languages

Call `initCloverI18n` near your app's entry point, before Clover draws:

```jsx
import { initCloverI18n } from "@nulib/clover";

initCloverI18n({ languages: ["fr", "en"] });
```

| Option        | Type                                       | Default                                |
| :------------ | :----------------------------------------- | :------------------------------------- |
| `languages`   | `string` or `string[]`                     | The page's `<html lang>`, else English |
| `lng`         | `string`                                   | One language, as `languages: [lng]`    |
| `fallbackLng` | `string`, `string[]` or `false`            | None; English is always last           |
| `resources`   | `{ [lng]: { clover: { [key]: string } } }` | None                                   |

It can be called again: each call merges its `resources` and applies any `languages`,
`lng` or `fallbackLng` it is given, and every Clover part on the page changes language at
once. The web components take the same call; see
[Languages](/docs/technical#languages) in the technical overview.

To speak one language whatever the visitor's, choose it, as the visitor would:

```jsx
import { initCloverI18n } from "@nulib/clover";

initCloverI18n().chooseInterfaceLanguage("fr");
```

## A language Clover does not ship

Give its strings as `resources`, under the `clover` namespace:

```jsx
import { initCloverI18n } from "@nulib/clover";

initCloverI18n({
  languages: ["de"],
  resources: {
    de: {
      clover: {
        commonClose: "Schließen",
        informationPanelTabs: "Informationsbereich",
      },
    },
  },
});
```

Any string you leave out falls back to English, marked `lang="en"`. The full list of
keys, with their English, is
[`en.json`](https://github.com/nulib-ds/clover/blob/main/packages/clover/src/i18n/locales/en.json).
A string with `{{name}}` in it is filled in by Clover: keep each placeholder as it is.

## Loading

English comes with Clover. Each other language is its own file, loaded the first time
Clover is to speak it, so a page in English never fetches one. Until it arrives, the
interface's words are shown in English, marked `lang="en"`, and they change when it does.
A page rendered on the server, or a test, that needs them in place first waits for them:

```js
await initCloverI18n({ languages: ["fr"] }).ready();
```

## Marking languages

Where a word of Clover's interface is not in the page's language (French on an English
page, or a string that fell back to English), the element that shows it, or is named by
it, carries its language as `lang`, so a screen reader pronounces it correctly (WCAG
3.1.2). The page's language is the `lang` of the `Root`'s nearest parent that has one, or
one you give the `Root`. A component of your own does the same with `useT` and
`useLangOf`, as [Languages](/docs/composing/customizing#languages) in Customizing layouts
shows.

Text in a language written right to left (Arabic, Hebrew, Persian, Urdu…) carries
`dir="rtl"` beside its `lang`, so its words run and its punctuation sits as they are
written on a page written either way: the interface's words in such a language, and the
resource's labels, summaries, metadata and annotations alike. Text in a language written
left to right takes the page's direction. Fields are the exception: a search field's
direction follows what is typed, not its placeholder.

## Adding a language to Clover

A language added to Clover itself ships to everyone. In
[nulib-ds/clover](https://github.com/nulib-ds/clover):

1. Add `packages/clover/src/i18n/locales/<tag>.json`, with every key `en.json` has,
   translated. Keep each `{{name}}` placeholder as it is.
2. Add its loader to `loaders` in `packages/clover/src/i18n/locales/index.ts`, so it
   loads only when it is needed.
3. Run `npm test`. `locales.test.ts` checks that the file has every key English has and
   no other, and that each placeholder is kept. A word your language spells as English
   does (French "Collection") goes on that test's `SAME_AS_ENGLISH` list for your
   language.
4. Add a line under `## Unreleased` in `packages/clover/CHANGELOG.md`, and open a pull
   request.

```json filename="packages/clover/src/i18n/locales/de.json"
{
  "commonClose": "Schließen",
  "commonNext": "Weiter",
  "commonPrevious": "Zurück"
}
```

```ts filename="packages/clover/src/i18n/locales/index.ts"
export const loaders: Record<string, LocaleLoader> = {
  de: () => import("./de.json"),
  es: () => import("./es.json"),
  // …
};
```

For a regional variant, name the file by its full tag (`fr-CA.json`) and give its loader
the same key (`"fr-CA"`); `fr-CA` gets it, and other French the base language.

A new key in `en.json` is added to every locale, translated, in the same change, and the
test fails until it is. If you speak one of the languages Clover ships, a review of its
strings is welcome, as an issue or a pull request.
