## API Reference

`Viewer` is the package's default export. It draws its `template`, and hands every other
prop to it: the template's own, below, and those of [`Root`](/docs/composing#root), which
every template is built on.

### Viewer

| Prop                   | Type                                 | Default              | Description                                                                        |
| ---------------------- | ------------------------------------ | -------------------- | ---------------------------------------------------------------------------------- |
| `iiifContent`          | `string \| object`                   | Required             | What to show: a URL, or a IIIF resource or content state as an object.             |
| `template`             | `Template`                           | `Default`, on demand | The layout: one from `@nulib/clover/templates`, or your own.                       |
| `canvasId`             | `string`                             | —                    | The Canvas to show, controlled: moving asks `onCanvasChange` to change it.         |
| `defaultCanvasId`      | `string`                             | —                    | The Canvas to start on. A content state or the Manifest's `start` still wins.      |
| `onCanvasChange`       | `(canvasId: string) => void`         | —                    | The reader moved to a Canvas.                                                      |
| `manifestId`           | `string`                             | —                    | In a Collection, the Manifest to show, controlled, with `onManifestChange`.        |
| `onManifestChange`     | `(manifestId: string) => void`       | —                    | In a Collection, the reader moved, or asks to move, to a Manifest.                 |
| `searchQuery`          | `string`                             | —                    | A Content Search query, run once the Manifest shows and whenever it changes.       |
| `annotations`          | `string \| object \| array`          | —                    | Annotation pages or collections to show beside the Manifest's own.                 |
| `annotationPages`      | `"view" \| "all"`                    | `"view"`             | Whose referenced annotation pages to fetch: the view's, or every Canvas's at once. |
| `onContentStateChange` | `(state: { json, encoded }) => void` | —                    | Where the reader is, as a content state, whenever it settles.                      |
| `onStatusChange`       | `(status, error) => void`            | —                    | The resource is `"loading"`, `"ready"`, or met an `"error"`.                       |
| `request`              | `{ credentials, headers, fetch }`    | —                    | Credentials, headers and a `fetch` of your own, for every request.                 |
| `language`             | `string`                             | The reader's         | The language to read IIIF text in.                                                 |
| `renderers`            | `ContentRenderer[]`                  | —                    | Components of your own for views Clover does not draw.                             |

`iiifContent` can be:

- **A Manifest**, shown from its `start` Canvas, or its first.
- **A Collection.** Its first Manifest is shown, or the one `manifestId` names, and its
  members are listed in the panel's Collection section. Paged Collections are followed
  through `next`, and a nested Collection is entered.
- **A Canvas**, shown on its own. Where it is `partOf` a Manifest, About names it, with a
  button that opens the Manifest at this Canvas.
- **A content state**, as JSON or base64url. It opens at the Canvas it points to, framing
  its region or seeking to its time. One that carries a `body` shows that note on the
  Canvas, as an annotation.
- **Annotations**: an AnnotationPage or AnnotationCollection made apart from any
  Manifest. The Viewer opens the first one's Manifest at its Canvas.
- **An object** of any of these. It is known by its `id`, so a new object with the same
  `id` does not reload.

Everything is upgraded to IIIF Presentation 4 as it loads, so every part reads one shape.
`toPresentation4()` does the same for data you hold yourself.

### Default

The Viewer's own layout, drawn when it is given no `template`: the title over the stage,
the thumbnails under it, and the information panel beside them, as in Clover 3.x.

| Prop               | Type                                      | Default                     | Description                                                       |
| ------------------ | ----------------------------------------- | --------------------------- | ----------------------------------------------------------------- |
| `header`           | `boolean`                                 | `true`                      | The thumbnail and title over the stage.                           |
| `headingLevel`     | `number`                                  | `2`                         | The title's level; the panel's sections are a level below.        |
| `panel`            | `boolean`                                 | `true`                      | The information panel and its toggle.                             |
| `download`         | `boolean`                                 | `true`                      | The downloads in the panel's About, where there is a `rendering`. |
| `defaultPanelOpen` | `boolean`                                 | Open where it fits          | Whether the panel starts open.                                    |
| `panelLayout`      | `"accordion" \| "tabs"`                   | `"accordion"`               | The panel's sections as stacked boxes, or as tabs.                |
| `items`            | `"carousel" \| "list" \| "grid" \| false` | `"carousel"`                | The thumbnails under the stage, or none.                          |
| `storageKey`       | `string \| false`                         | `"clover-template-default"` | Where the panel's width is remembered; `false` forgets it.        |
| `fill`             | `boolean`                                 | `false`                     | Fill the box it sits in; the stage takes what the rest leave.     |

### Document

Reads like a PDF viewer: a toolbar with the title and Download, page thumbnails down the
left, the pages down one column, and the information panel sliding out on the right.

| Prop                 | Type                    | Default                      | Description                                                    |
| -------------------- | ----------------------- | ---------------------------- | -------------------------------------------------------------- |
| `defaultSidebarOpen` | `boolean`               | Open on a wide screen        | Whether the page thumbnails start shown.                       |
| `defaultPanelOpen`   | `boolean`               | `false`                      | Whether the information panel starts open.                     |
| `panelLayout`        | `"accordion" \| "tabs"` | `"accordion"`                | The panel's sections as stacked boxes, or as tabs.             |
| `download`           | `boolean`               | `true`                       | Download's links in the toolbar, where there is a `rendering`. |
| `headingLevel`       | `number`                | `2`                          | The title's level; the panel's sections are a level below.     |
| `storageKey`         | `string \| false`       | `"clover-template-document"` | Where the thumbnails' width is remembered; `false` forgets it. |

### Gallery

A grid of the views, a spread one cell, that opens one in a lightbox to pan, zoom and
page through.

| Prop           | Type     | Default | Description                                           |
| -------------- | -------- | ------- | ----------------------------------------------------- |
| `size`         | `string` | `10rem` | A cell's width (sets `--clover-items-size`).          |
| `headingLevel` | `number` | `2`     | The title's level; the lightbox's title is one below. |

## Examples

### Templates

Pass a template from `@nulib/clover/templates` as `template`. A page loads only the
template it passes, and the parts that template uses: a Gallery loads no information
panel.

Given none, the Viewer loads `Default` the first time it draws, as a chunk of its own: one
request before the Manifest loads, and nothing drawn on the server. To have it up front,
pass it like any other.

```jsx
import { Default } from "@nulib/clover/templates";

<Viewer iiifContent={url} template={Default} />;
```

Every template is built only from parts `@nulib/clover` exports. To change one, copy its
source, in `packages/clover/src/templates/`, into your app: the
[Default template](/docs/viewer/default) walks through the Viewer's own, region by
region. To start from nothing, see [Composing Layouts](/docs/composing).

### Header and panel

Use `header={false}` to leave out the title over the stage, and `panel={false}` to leave
out the information panel and its toggle. `defaultPanelOpen` starts the panel open or
closed.


</ViewerExample>

### Fill

Use `fill` to have the Viewer fill a box of a set height, the window under a page's own
header, say. The stage takes what the title and the thumbnails leave, never less than
16rem; a shorter box scrolls.

<ViewerExample resource="print" box="34rem">

```jsx
<div style={{ height: "34rem" }}>
  <Viewer
    iiifContent="https://nulib-ds.github.io/clover/mocks/tagging/manifest.json"
    fill
  />
</div>
```

</ViewerExample>

### Heading level

Use `headingLevel` to fit the Viewer into the page's outline. Its title is an `h2`, and
the panel's sections `h3`s. Under a heading of your own, pass the level below it: the
Viewers on this page sit under `h3`s, and pass `4`.

```jsx
<h3>The catalog</h3>
<Viewer iiifContent={url} headingLevel={4} />
```

With `header={false}` there is no title, and the panel's sections take its place, at
`headingLevel` itself.

### Collection

Give a Collection as `iiifContent`, and the Viewer shows its first Manifest and lists its
members in the panel's Collection section. Choosing one shows it. `manifestId` with
`onManifestChange` makes the Manifest controlled, as `canvasId` does the Canvas.

<ViewerExample resource="https://api.dc.library.northwestern.edu/api/v2/collections/c373ecd2-2c45-45f2-9f9e-52dc244870bd?as=iiif">

```jsx
<Viewer iiifContent="https://api.dc.library.northwestern.edu/api/v2/collections/c373ecd2-2c45-45f2-9f9e-52dc244870bd?as=iiif" />
```

</ViewerExample>

### Opening at a place

Give a content state as `iiifContent` to open at a Canvas, framing a region of it
(`xywh=`) or seeking to a time (`t=`). This one opens the catalog at Page 4, framed on the
plate its "Then" tags.

<ViewerExample resource="catalog" place={{ canvas: 4, xywh: "2705,66,1419,1518" }}>

```jsx
import Viewer, { encodeContentState } from "@nulib/clover";

const state = {
  type: "Annotation",
  motivation: ["contentState"],
  target: {
    type: "SpecificResource",
    source: {
      id: "https://nulib-ds.github.io/clover/mocks/paged/canvas/5",
      type: "Canvas",
      partOf: [
        {
          id: "https://nulib-ds.github.io/clover/mocks/paged/manifest.json",
          type: "Manifest",
        },
      ],
    },
    selector: { type: "FragmentSelector", value: "xywh=2705,66,1419,1518" },
  },
};

<Viewer iiifContent={encodeContentState(state)} />;
```

</ViewerExample>

`onContentStateChange` hands you a content state whenever the reader settles: the Canvas
and region, or the moment in a recording, they are at. Put it in a link to share it.

```jsx
<Viewer
  iiifContent={url}
  onContentStateChange={({ encoded }) =>
    history.replaceState(null, "", `?iiif-content=${encoded}`)
  }
/>
```

### Annotations

Annotations on the Manifest's Canvases (comments, tags, transcriptions) are listed in the
panel's Annotations section and drawn on the Canvas. Picking one frames it, moving to its
Canvas first. This print has the words on its plate tagged where they sit.

<ViewerExample resource="print">

```jsx
<Viewer iiifContent="https://nulib-ds.github.io/clover/mocks/tagging/manifest.json" />
```

</ViewerExample>

Use `annotations` to show pages of your own beside the Manifest's.

```jsx
<Viewer iiifContent={url} annotations={annotationPageUrl} />
```

### Content Search

A Manifest with a IIIF Content Search service, version 1 or 2, gets a Search section: its
hits listed by page and drawn on the Canvas. Use `searchQuery` to search as it opens. None
of the homepage's resources has a search service, so this is Clover's newspaper
[mock](/docs/mocks), searched for "Moskau".

<ViewerExample resource="search" props={{ searchQuery: "Moskau" }}>

```jsx
<Viewer
  iiifContent="https://nulib-ds.github.io/clover/mocks/content-search/manifest.json"
  searchQuery="Moskau"
/>
```

</ViewerExample>

### Video and sound

Video and sound play in the Canvas's own controls. Their captions are drawn over the
picture and listed in the Transcript section, chapters come from the Manifest's Ranges,
and an annotation can follow a region through time (`xywh=…&t=…`). This reel follows
Rudolf Hess through the Nuremberg sentencing.

<ViewerExample resource="footage">

```jsx
<Viewer iiifContent="https://nulib-ds.github.io/clover/mocks/rudolf-hess-nuremberg/manifest.json" />
```

</ViewerExample>

### Animation

A Canvas whose images are timed, one per frame, plays as an animation, with a frame bar to
step, scrub and pause it. `auto-advance` plays it on arrival and `repeat` loops it.
Nothing plays for a reader who asks for reduced motion.

<ViewerExample resource="animation">

```jsx

```

</ViewerExample>

### Requests

Use `request` for every request the Viewer makes: the Manifest, annotation pages,
`info.json`, image tiles, captions and HLS segments.

```jsx
<Viewer
  iiifContent={url}
  request={{
    credentials: "include",
    headers: { Authorization: `Bearer ${token}` },
  }}
/>
```

A `<video>` element cannot send headers, so plain video and sound get only the
credentials. So does an image served without CORS, which Clover shows as an `<img>`.

### Renderers

Use `renderers` to draw the views Clover does not, a 3D model or a PDF, with components of
your own. See [Renderers of your own](/docs/composing#renderers-of-your-own).

### Styles

Import `@nulib/clover/styles.css` once, and `@nulib/clover/templates.css` for Document
and Gallery. Size the stage with `--clover-content-height`.

```css
.catalog {
  --clover-content-height: 32rem;
}
```

The rest is in [Composing Layouts](/docs/composing#styles).

## From Clover 3.x

Clover 3.x's Viewer, `@samvera/clover-iiif`, is documented at
[Clover 3.x › Viewer](/docs/3.x/viewer). Its `iiifContentSearchQuery` is `searchQuery`,
and its `customDisplays` are `renderers`. Its `options.informationPanel` is set out on
[Panel](/docs/panel).
