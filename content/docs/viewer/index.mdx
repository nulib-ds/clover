## API reference

`Viewer` is the package's default export. It draws its `template`, and hands every other
prop to it: the template's own, below, and those of [`Root`](/docs/composing#root), which
every template is built on.

<ApiReference elements="clover-viewer">

### Viewer

| Prop                   | Type                                 | Default                      | Description                                                                                                                                                    |
| ---------------------- | ------------------------------------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `iiifContent`          | `string \| object`                   | Required                     | What to show: a URL, or a IIIF resource or content state as an object.                                                                                         |
| `template`             | `Template`                           | `Default`, on demand         | The layout: one from `@nulib/clover/templates`, or your own.                                                                                                   |
| `canvasId`             | `string`                             | —                            | The Canvas to show, controlled: moving asks `onCanvasChange` to change it.                                                                                     |
| `defaultCanvasId`      | `string`                             | —                            | The Canvas to start on. A content state or the Manifest's `start` still wins.                                                                                  |
| `onCanvasChange`       | `(canvasId: string) => void`         | —                            | The current Canvas changed.                                                                                                                                    |
| `manifestId`           | `string`                             | —                            | In a Collection, the Manifest to show, controlled, with `onManifestChange`.                                                                                    |
| `defaultManifestId`    | `string`                             | —                            | In a Collection, the Manifest to open first.                                                                                                                   |
| `onManifestChange`     | `(manifestId: string) => void`       | —                            | In a Collection, another Manifest opened, or was asked for.                                                                                                    |
| `searchQuery`          | `string`                             | —                            | A Content Search query, run once the Manifest shows and whenever it changes.                                                                                   |
| `annotations`          | `string \| object \| array`          | —                            | Annotation pages or collections to show beside the Manifest's own.                                                                                             |
| `annotationPages`      | `"view" \| "all"`                    | `"view"`                     | Whose referenced annotation pages to fetch: the view's, or every Canvas's at once.                                                                             |
| `onContentStateChange` | `(state: { json, encoded }) => void` | —                            | The current view, as a content state, as it changes.                                                                                                           |
| `onStatusChange`       | `(status, error) => void`            | —                            | The resource is `"loading"`, `"ready"`, or met an `"error"`.                                                                                                   |
| `request`              | `{ credentials, headers, fetch }`    | —                            | Credentials, headers and a `fetch` of your own, for every request.                                                                                             |
| `language`             | `string`                             | The page's, or the browser's | The language to read IIIF text in.                                                                                                                             |
| `highContrast`         | `boolean`                            | `false`                      | Clover's higher-contrast mode: the accent kept to rings, outlines and marks, never under words or a glyph. On wherever the system asks for more contrast, too. |
| `renderers`            | `BodyRenderer[]`                     | —                            | Components of your own for views Clover does not draw.                                                                                                         |

`iiifContent` can be:

- **A Manifest**, shown from its `start` Canvas, or its first.
- **A Collection.** Its first Manifest is shown, or the one `manifestId` names, and its
  members are listed in the panel's Collection section. Paged Collections are followed
  through `next`, and a nested Collection is entered.
- **A Canvas**, shown on its own. Where it is `partOf` a Manifest, About names it, with a
  button that opens the Manifest at this Canvas.
- **A content state**, as JSON or base64url. It opens at the Canvas it points to, framing
  its region or seeking to its time. One that carries a `body` shows that note on the
  Canvas, as an annotation.
- **Annotations**: an AnnotationPage or AnnotationCollection made apart from any
  Manifest. The Viewer opens the first one's Manifest at its Canvas.
- **An object** of any of these. It is known by its `id`, so a new object with the same
  `id` does not reload.

Everything is upgraded to IIIF Presentation 4 as it loads, so every part reads one shape.
`toPresentation4()` does the same for data you hold yourself.

### Default

The Viewer's own layout, drawn when it is given no `template`: the title over the Body,
the thumbnails under it, and the information panel beside them, as in Clover 3.x. More
on [its own page](/docs/viewer/default).

| Prop               | Type                                    | Default                     | Description                                                                                                                                                                                        |
| ------------------ | --------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `header`           | `boolean`                               | `true`                      | The title and provider over the Body; opened on a Collection, the Collection's title over the Manifest's and a pager among its members; for a content state's several targets, a pager among them. |
| `headingLevel`     | `number`                                | `2`                         | The title's level; the panel's sections are a level below.                                                                                                                                         |
| `panel`            | `boolean`                               | `true`                      | The information panel and its toggle.                                                                                                                                                              |
| `download`         | `boolean`                               | `true`                      | The downloads in the panel's About, where there is a `rendering`.                                                                                                                                  |
| `languages`        | `boolean`                               | `true`                      | The languages to read the resource in, beside the panel's About heading, where it comes in several; `false` leaves the choice out.                                                                 |
| `defaultPanelOpen` | `boolean`                               | `true`                      | Whether the panel starts open beside the Body; over it, closed.                                                                                                                                    |
| `panelLayout`      | `"accordion" \| "tabs"`                 | `"accordion"`               | The panel's sections as stacked boxes, or as tabs.                                                                                                                                                 |
| `panelSections`    | `PanelSection[]`                        | All                         | Which of the panel's sections it may have; each still shows only where the resource has data for it, and no panel at all where it has none of them.                                                |
| `panelLabels`      | `PanelSectionLabels`                    | —                           | What a panel section says, in place of Clover's own word for it: text, or text by language tag.                                                                                                    |
| `items`            | `"slider" \| "list" \| "grid" \| false` | `"slider"`                  | The thumbnails under the Body, or none.                                                                                                                                                            |
| `singleItem`       | `boolean`                               | `false`                     | The thumbnails even where the resource has one view.                                                                                                                                               |
| `storageKey`       | `string \| false`                       | `"clover-template-default"` | Where the panel's width is remembered; `false` forgets it.                                                                                                                                         |
| `fill`             | `boolean`                               | `false`                     | Fill the box it sits in; the Body takes what the rest leave.                                                                                                                                       |
| `collapseControls` | `"auto" \| "always"`                    | `"auto"`                    | When the Body's view controls (zoom, rotation, reset, full screen) collapse behind one button: only where its row cannot hold them all, or always, leaving the media more room.                    |

## Examples

### Templates

Pass a template from `@nulib/clover/templates` as `template`. A page loads only the
template it passes, and the parts that template uses: a Gallery loads no information
panel.

Given none, the Viewer loads `Default` the first time it draws, as a chunk of its own: one
request before the Manifest loads, and nothing drawn on the server. To have it up front,
pass it like any other.

```jsx
import { Default } from "@nulib/clover/templates";

<Viewer iiifContent={url} template={Default} />;
```

Every template is built only from parts `@nulib/clover` exports. To change one, copy its
source, in `packages/clover/src/templates/`, into your app. To start from nothing, see
[Composing layouts](/docs/composing).

### Panel layout

Use `panelLayout` to lay the information panel's sections out as tabs rather than stacked

### Panel sections

Use `panelSections` to keep the panel to some of Clover's own sections: it leaves About,
the Collection or any other out, and each of the rest still shows only where the resource
has data for it ([Panel](/docs/panel#only-some-of-them)). Where it has none of them there
is no panel at all: no pane, no bar and no toggle. `panelLabels` says what a section's tab
or heading says, in place of Clover's own word for it.

```jsx
<Viewer
  iiifContent={url}
  panelSections={["contents", "search", "transcript", "annotations"]}
/>
```

```html twin
<clover-viewer
  iiif-content="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json"
  panel-sections="contents search transcript annotations"
></clover-viewer>
```

### Heading level

Use `headingLevel` to fit the Viewer into the page's outline. Its title is an `h2`, and
the panel's sections `h3`s. Under a heading of your own, pass the level below it: the
Viewers on this page sit under `h3`s, and pass `4`.

```jsx
<h3>The catalog</h3>
<Viewer iiifContent={url} headingLevel={4} />
```

With `header={false}` there is no title, and the panel's sections take its place, at
`headingLevel` itself.

Every template's title is a heading at that level, and its size is your page's for it:
Clover sets none, only a regular weight, so a title given `h4` looks as your other `h4`s
do. Style it by its level or by `.clover-title` ([Styling](/docs/styling#headings)).

### Collection

Give a Collection as `iiifContent`, and the Viewer shows its first Manifest and lists its
members in the panel's Collection section. Choosing one shows it. `manifestId` with
`onManifestChange` makes the Manifest controlled, as `canvasId` does the Canvas.

<ViewerExample resource="https://api.dc.library.northwestern.edu/api/v2/collections/c373ecd2-2c45-45f2-9f9e-52dc244870bd?as=iiif">

```jsx
<Viewer iiifContent="https://api.dc.library.northwestern.edu/api/v2/collections/c373ecd2-2c45-45f2-9f9e-52dc244870bd?as=iiif" />
```

</ViewerExample>

### Opening at a place

Give a content state as `iiifContent` to open at a Canvas, framing a region of it
(`xywh=`) or seeking to a time (`t=`). This one opens the catalog at Page 4, framed on the
plate its "Then" tags.

<ViewerExample resource="catalog" place={{ canvas: 4, xywh: "2705,66,1419,1518" }}>

```jsx
import Viewer, { encodeContentState } from "@nulib/clover";

const state = {
  type: "Annotation",
  motivation: ["contentState"],
  target: {
    type: "SpecificResource",
    source: {
      id: "https://clover.iiif.library.northwestern.edu/mocks/paged/canvas/5",
      type: "Canvas",
      partOf: [
        {
          id: "https://clover.iiif.library.northwestern.edu/mocks/paged/manifest.json",
          type: "Manifest",
        },
      ],
    },
    selector: { type: "FragmentSelector", value: "xywh=2705,66,1419,1518" },
  },
};

<Viewer iiifContent={encodeContentState(state)} />;
```

<clover-viewer></clover-viewer>

          {

          },

</ViewerExample>

`onContentStateChange` hands you a content state as the view changes: the Canvas and
region, or the moment in a recording, it is at
([Content State](/docs/content-state)). Put it in a link to share it.

```jsx
<Viewer
  iiifContent={url}
  onContentStateChange={({ encoded }) =>
    history.replaceState(null, "", `?iiif-content=${encoded}`)
  }
/>
```

```html twin
<clover-viewer
  iiif-content="https://clover.iiif.library.northwestern.edu/mocks/paged/manifest.json"
></clover-viewer>

<script type="module">
  document
    .querySelector("clover-viewer")
    .addEventListener("clover-content-state-change", ({ detail }) =>
      history.replaceState(null, "", `?iiif-content=${detail.encoded}`),
    );
</script>
```

Annotations on the Manifest's Canvases (comments, tags, transcriptions) are listed in the
panel's Annotations section and drawn on the Canvas. Picking one frames it, moving to its
Canvas first. This catalog has each plate's "Then" and "Now" tagged where they are.

<ViewerExample resource="catalog">

</ViewerExample>

```jsx
<Viewer iiifContent={url} annotations={annotationPageUrl} />

### Content Search

A Manifest with a IIIF Content Search service, version 1 or 2, gets a Search section: its
hits listed by page and drawn on the Canvas, the first gone to as they arrive. Use
`searchQuery` to search as it opens. This is the homepage's catalog, its words read by
machine and searchable ([mock](/docs/mocks)), searched for "steel".

  iiifContent="https://clover.iiif.library.northwestern.edu/mocks/paged/manifest.json"
  searchQuery="steel"

```

</ViewerExample>

### Video and sound

Video and sound play in the Canvas's own controls. Their captions are drawn over the
picture and listed in the Transcript section, chapters come from the Manifest's Ranges,
and an annotation can follow a region through time (`xywh=…&t=…`). In this example,
Clover plays a film whose annotations each follow a region as it moves, with its
captions and chapters beside it.

<ViewerExample resource="footage">

```jsx
<Viewer iiifContent="https://clover.iiif.library.northwestern.edu/mocks/rudolf-hess-nuremberg/manifest.json" />
```

</ViewerExample>

### Animation

A Canvas whose images are timed, one per frame, plays as an animation over the Canvas's
own `duration`: a seek bar over its time, each frame's start marked as a chapter's is, the
time, Previous and Next to step from one frame to the next, and the frames listed by their
labels. Each frame shows for its own span, so frames timed together show together. A
frame may be a video or sound, which plays from its own start in its region, or text,
drawn in its region and read by screen readers outside the picture.
`auto-advance` plays it on arrival and `repeat` loops it. Nothing plays where reduced
motion is asked for.

<ViewerExample resource="animation">

```jsx
<Viewer iiifContent="https://nulib-ds.github.io/muybridge/iiif/plate-number-700-buffalo-galloping.json" />
```

</ViewerExample>

### Requests

Use `request` for every request the Viewer makes: the Manifest, annotation pages,
`info.json`, image tiles, captions and HLS segments.

```jsx
<Viewer
  iiifContent={url}
  request={{
    credentials: "include",
    headers: { Authorization: `Bearer ${token}` },
  }}
/>
```

```html twin
<clover-viewer
  iiif-content="https://clover.iiif.library.northwestern.edu/mocks/paged/manifest.json"
></clover-viewer>

<script type="module">
  document.querySelector("clover-viewer").request = {
    credentials: "include",
    headers: { Authorization: `Bearer ${token}` },
  };
</script>
```

A `<video>` element cannot send headers, so plain video and sound get only the
credentials. So does an image served without CORS, which Clover shows as an `<img>`.

### Renderers

Use `renderers` to draw a view with a component of your own: one Clover does not draw, a
PDF say, or one you want drawn otherwise. See
[Custom renderer](/docs/composing#custom-renderer).

### Styles

Import `@nulib/clover/styles.css` once, and `@nulib/clover/templates.css` for Document
and Gallery. Size the Body with `--clover-body-height`.

```css
.catalog {
  --clover-body-height: 32rem;
}
```

The rest is in [Styling](/docs/styling).

## From Clover 3.x

Clover 3.x's Viewer, `@samvera/clover-iiif`, is documented at
[Clover 3.x › Viewer](/docs/deprecated-versions/viewer). Its `iiifContentSearchQuery` is `searchQuery`,
and its `customDisplays` are `renderers`. Its `options.informationPanel` is set out on
[Panel](/docs/panel).
