# Get Started

Clover builds interfaces for IIIF content in React or as a web component: a Manifest, a
Collection, a Canvas or a content state, read through the IIIF Presentation API. It is
accessible, composable and light, and it draws images, video and sound with a renderer of
its own.

Clover is used two ways.

- **The Viewer**, ready-made. Give it a Manifest, and a template for a layout other than
  the default.

  ```jsx
  import Viewer from "@nulib/clover";
  import { Document } from "@nulib/clover/templates";

  <Viewer iiifContent={url} />
  <Viewer iiifContent={url} template={Document} />
  ```

- **The parts** it is built from, for a layout of your own. Each reads from the nearest
  `Root`, wherever it sits in your markup: see [Composing Layouts](/docs/composing).

  ```jsx
  import * as Clover from "@nulib/clover";

  <Clover.Root iiifContent={url}>
    <Clover.Label as="h1" />
    <Clover.Content />
    <Clover.Items layout="pager" />
    <Clover.Items />
  </Clover.Root>;
  ```

A page loads only the template it uses, and the parts tree-shake: a page that never draws
an information panel never loads one.

## Install

```bash
npm install @nulib/clover
```

Import the stylesheet once, beside the components:

```jsx
import "@nulib/clover/styles.css";
```

Clover takes its type and its sizes from your page: it sets no font, and every space is
a step from your `1rem`.

## Imports

| Import                         | What it is                                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `@nulib/clover`                | The [Viewer](/docs/viewer) (the default export), and every part, hook and helper (named).                   |
| `@nulib/clover/templates`      | The [templates](/docs/viewer#templates): `Default`, `Document` and `Gallery`.                               |
| `@nulib/clover/map`            | [`Map`](/docs/map), for navPlace and georeferenced images. The Viewer adds its Map tab itself.              |
| `@nulib/clover/web-components` | [`<clover-viewer>`](#web-component), and [parts as elements](#parts-as-elements), for a page without React. |
| `@nulib/clover/styles.css`     | Every part's styles, and the `Default` template's.                                                          |
| `@nulib/clover/templates.css`  | The other templates' styles.                                                                                |

React 18 and 19 are supported. The package is ES modules only.

## Web component

`<clover-viewer>` is the 4.x Viewer as a custom element, for a page without React: a CMS
template, a static site, an exhibit page. It is built on its own, with
[Preact](https://preactjs.com/) standing in for React, and carries Clover's stylesheet.

```html
<script src="https://cdn.example.org/@nulib/clover/dist/web-components/index.umd.js"></script>

<clover-viewer
  iiif-content="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json"
></clover-viewer>
```

`index.umd.js` is a classic script that loads the element's module from beside itself, so
it works from any CDN path. On a page with modules, load
`web-components/index.mjs` with `<script type="module">` instead.

### Attributes

| Attribute       | What it does                                                         |
| --------------- | -------------------------------------------------------------------- |
| `iiif-content`  | What to show: a URL, or a content state.                             |
| `canvas-id`     | The Canvas to open on.                                               |
| `manifest-id`   | In a Collection, the Manifest to open first.                         |
| `language`      | The language to read IIIF text in.                                   |
| `search-query`  | A Content Search to run as the Manifest opens.                       |
| `items`         | `carousel` (default), `list`, `grid`, or `false` for no thumbnails.  |
| `header`        | `false` removes the thumbnail and title over the stage.              |
| `heading-level` | The title's level, `2` (default) or more, to fit the page's outline. |
| `panel`         | `false` removes the information panel.                               |
| `download`      | `false` leaves the downloads out of the panel's About.               |

`false` is read in any case. An `items` value not in the list shows the carousel, with a
warning in the console. With `header="false"` there is no title, and the panel's sections
take `heading-level` themselves.

The `iiifContent` property takes a IIIF object as well, which an attribute cannot carry,
set before the element's script has loaded or after:

```js
document.querySelector("clover-viewer").iiifContent = manifestJson;
```

### Languages

Clover's own words follow the page's `<html lang>`, then the reader's browser, as in React. The element carries its own
copy of Clover's translator, so a page sets their language, or adds strings, through the
element: `initCloverI18n` from the module, or from any element's class in a classic
script. It applies to every Clover element on the page.

```js
// With modules.
import { initCloverI18n } from ".../web-components/index.mjs";
initCloverI18n({ lng: document.documentElement.lang });

// From a classic script, once the element is defined.
customElements.get("clover-viewer").initCloverI18n({ lng: "fr" });
```

Where that language is not the page's, the viewer marks each of its own words with
`lang`, as a `Root` does; see [Languages](/docs/composing#languages).

### Events

Each is `clover-` and what happened, bubbling, so a page can listen for it anywhere above
the element.

| Event                         | `detail`                                      |
| ----------------------------- | --------------------------------------------- |
| `clover-canvas-change`        | `{ canvasId }`                                |
| `clover-manifest-change`      | `{ manifestId }`, in a Collection             |
| `clover-status-change`        | `{ status, error }`, as it loads              |
| `clover-content-state-change` | `{ json, encoded }`, where the reader settles |

```js
viewer.addEventListener("clover-canvas-change", (event) => {
  console.log(event.detail.canvasId);
});
```

### Parts as elements

The parts compose in HTML too, inside a `<clover-root>`, as they do in JSX inside a
`Root`. Each draws its part into itself, wherever the page puts it in the root, and the
page's own markup between them stays as written.

```html
<clover-root
  iiif-content="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json"
>
  <clover-label as="h2"></clover-label>
  <clover-content style="height: 60vh"></clover-content>
  <p>Now showing <clover-label of="canvas"></clover-label>.</p>
  <clover-previous></clover-previous>
  <clover-position></clover-position>
  <clover-next></clover-next>
  <clover-summary></clover-summary>
  <clover-metadata></clover-metadata>
</clover-root>
```

| Elements                                                                                                                                                                                                                             | What they draw                                                                         | Attributes                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<clover-root>`                                                                                                                                                                                                                      | Nothing of its own: it loads what it is given, and its parts read where the reader is. | `iiif-content` (or the `iiifContent` property), `canvas-id` and `manifest-id` (where it opens; changed later, they move the reader), `language`, `search-query`, `annotations`.                          |
| `<clover-content>`                                                                                                                                                                                                                   | The view, on a stage as tall as `--clover-content-height` (60vh) or its own `style`.   | `controls` and `navigator` (`false` turns one off).                                                                                                                                                      |
| `<clover-items>`                                                                                                                                                                                                                     | Thumbnails of the views, or of the Collection's members.                               | `layout` (`carousel`, `list`, `grid` or `pager`), `of`, `navigation`, `thumbnail-size`; alone, `iiif-content`, `header`, `heading-level`.                                                                |
| `<clover-previous>`, `<clover-position>`, `<clover-next>`                                                                                                                                                                            | Stepping through the views, and where the reader is.                                   | `of` (`views` or `members`).                                                                                                                                                                             |
| `<clover-status>`                                                                                                                                                                                                                    | What the root is doing: loading, or why it failed.                                     | `loading="false"`, where the stage shows its own.                                                                                                                                                        |
| `<clover-label>`, `<clover-thumbnail>`, `<clover-summary>`, `<clover-metadata>`, `<clover-required-statement>`, `<clover-rights>`, `<clover-homepage>`, `<clover-see-also>`, `<clover-rendering>`, `<clover-part-of>`, `<clover-id>` | One IIIF property each, of the Manifest or the Canvas in view.                         | `of` (`manifest` or `canvas`); `value`, its own as text, a URL or JSON, which alone, outside a root, it shows; `as` on a label (a heading, `h1` to `h6`) and a summary; `size` and `alt` on a thumbnail. |
| `<clover-value>`                                                                                                                                                                                                                     | Any language map, as text, HTML or Markdown.                                           | `value`, `format`, `heading-level`, `as`.                                                                                                                                                                |
| `<clover-about>`, `<clover-annotations>`, `<clover-collection>`, `<clover-collection-select>`, `<clover-contents>`, `<clover-search>`, `<clover-transcript>`, `<clover-download>`                                                    | The information panel's sections, each on its own.                                     | `heading-level` (one under the heading they sit beneath), and each its own.                                                                                                                              |
| `<clover-map>`                                                                                                                                                                                                                       | The root's places and georeferenced images; alone, those of its `iiif-content`.        | `overlay`, `overlay-opacity`, `style-url`, `scroll-zoom`.                                                                                                                                                |

Every attribute, property and event is in the manifest, below. A part of a root draws
nothing outside one, and says so in the console. `<clover-root>` sends the same events as
`<clover-viewer>`; `<clover-items>` and `<clover-map>` send `clover-select` when an item
or a place is chosen (cancel it, with `preventDefault`, to keep a link from being
followed), and `<clover-collection-select>` sends `clover-change`. Give an element no
`aria-label` or `role`: it is a box no reader is told of, and Clover names what it draws
itself; a landmark of the page's own around an element names it otherwise.

### Types and the manifest

The module's types declare every element (`HTMLElementTagNameMap`) and every event, so
`document.querySelector("clover-root")` is typed. Its
[Custom Elements Manifest](https://github.com/webcomponents/custom-elements-manifest),
`@nulib/clover/web-components/custom-elements.json` (the package's `customElements`),
gives each element's attributes, properties and events to editors and tools.

### What it loads

The script is {loads.elementsEntry} kB gzipped: it defines every element and draws none.
An element's code loads the first time one is on the page, with Preact and the
stylesheet, so a page loads only the elements it uses: {loads.element} kB with a
`<clover-viewer>`, the Viewer in its Default template among it (3.x's element loads about
530 kB), and {loads.labels} kB for a `<clover-root>` and its `<clover-label>`s, as the
package's build measures them. Everything else waits until it is needed: video streaming
(hls.js), the sanitizer, an animation's player, and the map — MapLibre, its worker and its
stylesheet load the first time a map is shown.

The element renders into its own children, with no shadow root, so the page's CSS still
reaches it, as 3.x's does. Clover's stylesheet is added to the document once, first in
`<head>`, so the page's own rules win.

## Coming from Clover 3.x

| Clover 3.x                       | Clover 4                                                   |
| -------------------------------- | ---------------------------------------------------------- |
| `Viewer`                         | `Viewer`, in its `Default` template                        |
| `Slider`                         | [`Items`](/docs/items)                                     |
| `Image`                          | [`Canvas`](/docs/canvas), Clover's own renderer            |
| `Scroll`                         | Not in Clover 4 yet; see [Scroll in 3.x](/docs/3.x/scroll) |
| `Map`                            | [`Map`](/docs/map), on MapLibre                            |
| Primitives (`Label`, `Summary`…) | Parts of the same names, reading from the nearest `Root`   |
| `options`                        | Props on the parts, and CSS custom properties              |
| Information panel                | [`Panel`](/docs/panel)                                     |
| Information panel plugins        | `Clover.Tab`, and hooks such as `useActiveCanvas`          |
| `customDisplays`                 | `renderers`                                                |

The [Clover 3.x](/docs/3.x) docs are kept beside these.
