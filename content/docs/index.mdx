# Get Started

Clover builds interfaces for IIIF content in React or as a web component: a Manifest, a
Collection, a Canvas or a content state, read through the IIIF Presentation API. It is
accessible, composable and light, and it draws images, video and sound with a renderer of
its own.

Clover is used two ways.

- **The Viewer**, ready-made. Give it a Manifest, and a template for a layout other than
  the default.

  ```jsx
  import Viewer from "@nulib/clover";
  import { Document } from "@nulib/clover/templates";

  <Viewer iiifContent={url} />
  <Viewer iiifContent={url} template={Document} />
  ```

- **The parts** it is built from, for a layout of your own. Each reads from the nearest
  `Root`, wherever it sits in your markup: see [Composing Layouts](/docs/composing).

  ```jsx
  import * as Clover from "@nulib/clover";

  <Clover.Root iiifContent={url}>
    <Clover.Label as="h1" />
    <Clover.Content />
    <Clover.Items layout="pager" />
    <Clover.Items />
  </Clover.Root>;
  ```

A page loads only the template it uses, and the parts tree-shake: a page that never draws
an information panel never loads one.

## Install

```bash
npm install @nulib/clover
```

<Callout type="info">
  Clover 4 is in development and not on npm yet. The released Clover is 3.x,
  `@samvera/clover-iiif`; see [Clover 3.x](/docs/3.x).
</Callout>

Import the stylesheet once, beside the components:

```jsx
import "@nulib/clover/styles.css";
```

Clover takes its type and its sizes from your page: it sets no font, and every space is
a step from your `1rem`.

## Imports

| Import                         | What it is                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| `@nulib/clover`                | The [Viewer](/docs/viewer) (the default export), and every part, hook and helper (named).      |
| `@nulib/clover/templates`      | The [templates](/docs/viewer#templates): `Default`, `Document` and `Gallery`.                  |
| `@nulib/clover/map`            | [`Map`](/docs/map), for navPlace and georeferenced images. The Viewer adds its Map tab itself. |
| `@nulib/clover/web-components` | [`<clover-viewer>`](#web-component), for a page without React.                                 |
| `@nulib/clover/styles.css`     | Every part's styles, and the `Default` template's.                                             |
| `@nulib/clover/templates.css`  | The other templates' styles.                                                                   |

React 18 and 19 are supported. The package is ES modules only.

## Web component

`<clover-viewer>` is the 4.x Viewer as a custom element, for a page without React: a CMS
template, a static site, an exhibit page. It is built on its own, with
[Preact](https://preactjs.com/) standing in for React, and carries Clover's stylesheet.

```html
<script src="https://cdn.example.org/@nulib/clover/dist/web-components/index.umd.js"></script>

<clover-viewer
  iiif-content="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json"
></clover-viewer>
```

`index.umd.js` is a classic script that loads the element's module from beside itself, so
it works from any CDN path. On a page with modules, load
`web-components/index.mjs` with `<script type="module">` instead.

### Attributes

| Attribute           | What it does                                                         |
| ------------------- | -------------------------------------------------------------------- |
| `iiif-content`      | What to show: a URL, or a content state.                             |
| `canvas-id`         | The Canvas to open on.                                               |
| `manifest-id`       | In a Collection, the Manifest to show.                               |
| `language`          | The language to read IIIF text in.                                   |
| `search-query`      | A Content Search to run as the Manifest opens.                       |
| `items`             | `carousel` (default), `list`, `grid`, or `false` for no thumbnails.  |
| `header`            | `false` removes the thumbnail and title over the stage.              |
| `heading-level`     | The title's level, `2` (default) or more, to fit the page's outline. |
| `panel`, `download` | `false` removes the information panel or the Download button.        |

With `header="false"` there is no title, and the panel's sections take `heading-level`
themselves.

The `iiifContent` property takes a IIIF object as well, which an attribute cannot carry:

```js
document.querySelector("clover-viewer").iiifContent = manifestJson;
```

### Languages

Clover's own words follow the page's `<html lang>`, then the reader's browser, as in React. The element carries its own
copy of Clover's translator, so a page sets their language, or adds strings, through the
element: `initCloverI18n` from the module, or from the element's class in a classic
script. It applies to every `<clover-viewer>` on the page.

```js
// With modules.
import { initCloverI18n } from ".../web-components/index.mjs";
initCloverI18n({ lng: document.documentElement.lang });

// From a classic script, once the element is defined.
customElements.get("clover-viewer").initCloverI18n({ lng: "fr" });
```

Where that language is not the page's, the viewer marks each of its own words with
`lang`, as a `Root` does; see [Languages](/docs/composing#languages).

### Events

| Event                | `detail`                                      |
| -------------------- | --------------------------------------------- |
| `canvaschange`       | `{ canvasId }`                                |
| `manifestchange`     | `{ manifestId }`, in a Collection             |
| `contentstatechange` | `{ json, encoded }`, where the reader settles |

```js
viewer.addEventListener("canvaschange", (event) => {
  console.log(event.detail.canvasId);
});
```

### What it loads

About 90 kB gzip up front: the Viewer in its Default template, Preact and the stylesheet (3.x's element loads about
530 kB). Everything else waits until it is needed: video streaming (hls.js), the sanitizer,
an animation's player, and the map — MapLibre, its worker and its stylesheet load the first
time a map is shown.

The element renders into its own children, with no shadow root, so the page's CSS still
reaches it, as 3.x's does. Clover's stylesheet is added to the document once, first in
`<head>`, so the page's own rules win.

## Coming from Clover 3.x

| Clover 3.x                       | Clover 4                                                   |
| -------------------------------- | ---------------------------------------------------------- |
| `Viewer`                         | `Viewer`, in its `Default` template                        |
| `Slider`                         | [`Items`](/docs/items)                                     |
| `Image`                          | [`Canvas`](/docs/canvas), Clover's own renderer            |
| `Scroll`                         | Not in Clover 4 yet; see [Scroll in 3.x](/docs/3.x/scroll) |
| `Map`                            | [`Map`](/docs/map), on MapLibre                            |
| Primitives (`Label`, `Summary`…) | Parts of the same names, reading from the nearest `Root`   |
| `options`                        | Props on the parts, and CSS custom properties              |
| Information panel                | [`Panel`](/docs/panel)                                     |
| Information panel plugins        | `Clover.Tab`, and hooks such as `useActiveCanvas`          |
| `customDisplays`                 | `renderers`                                                |

The [Clover 3.x](/docs/3.x) docs are kept beside these.
