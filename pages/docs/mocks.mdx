# Mocks

IIIF resources Clover publishes for testing a viewer against: complete, valid, and stable
at their URLs. Each is generated from one source in `docs/mocks/`, so the published files,
the live service in `npm run dev`, and the docs' own demos always agree.

Use them from any viewer, test suite or prototype. Publish a new mock the same way when
it is complex enough to reuse: a generator in `docs/mocks/<name>/`, its files written to
`public/mocks/<name>/` by `npm run build:mocks`, and a section on this page.

## Content Search 2.0: a newspaper issue

Two pages of the _Berliner Tageblatt_ of 16 February 1925, with their OCR and a IIIF
Content Search 2.0 service. The OCR is the newspaper's own (Fraktur, errors included),
with a position for every word, so search hits and text land where the print is.

| Resource        | Published (static)                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Manifest        | [`/mocks/content-search/manifest.json`](https://nulib-ds.github.io/clover/mocks/content-search/manifest.json)                                                 |
| OCR, by line    | [`/mocks/content-search/ocr/p1-lines.json`](https://nulib-ds.github.io/clover/mocks/content-search/ocr/p1-lines.json), `p2-lines.json`                        |
| OCR, by word    | [`/mocks/content-search/ocr/p1-words.json`](https://nulib-ds.github.io/clover/mocks/content-search/ocr/p1-words.json), `p2-words.json`                        |
| Example answers | [`/mocks/content-search/search/examples/nicht.json`](https://nulib-ds.github.io/clover/mocks/content-search/search/examples/nicht.json) and others: see below |
| Search service  | `/mocks/content-search/search`: answered live by `npm run dev` or `mockFetch`, not by the static site                                                         |

All under `https://nulib-ds.github.io/clover`.

### What is in it

- **The Manifest** has two Canvases (3602 × 5000 and 3536 × 4999), drawn from the IIIF
  Image API reference server, and a `SearchService2`. Each Canvas references its OCR by
  line in `annotations`.
- **OCR pages** are AnnotationPages of `supplementing` annotations with a `TextualBody`
  (`language: "de"`) targeting the region it was read from, `canvas#xywh=x,y,w,h`, in the
  Canvas's pixels. Each carries a [`textGranularity`](https://iiif.io/api/extension/text-granularity/)
  of `line` (about 310 a page) or `word` (about 2,500 a page). The Manifest references
  only the lines; the words are there for testing word-level highlighting.
- **Search answers** follow Content Search 2.0:
  - `items` are `highlighting` annotations on each match's OCR box, a SpecificResource
    on the Canvas (with `partOf` naming the Manifest) and an `xywh=` FragmentSelector.
  - `annotations` holds a page of `contextualizing` annotations, one per hit, quoting it
    with a `TextQuoteSelector`: `prefix`, `exact` and `suffix`, six words either side.
  - Results come 25 to a page, in an AnnotationCollection (`partOf` with `total`,
    `first` and `last`), with `startIndex`, `prev` and `next`.
- **Matching** ignores case, accents and punctuation, and reads the Fraktur long s (ſ) as
  s. A word matches if it contains the query, so `berlin` finds "Berliner"; a phrase
  matches consecutive words, its box the union of theirs.

### Example answers

Static files, for tests that need a fixed answer. Each is exactly what the live service
returns for the query, except that page links point at the next file.

### Searching it live

A static site cannot read `?q=`, so the published search service URL answers nothing by
itself. Two ways to search any query:

- **`npm run dev`** serves a live copy of the whole mock, with every id under the dev
  server: `http://localhost:3000/api/mocks/content-search/manifest.json`. Its service
  answers any `q` and `page`, with `Access-Control-Allow-Origin: *` so a viewer on
  another port can use it.

  ```sh
  curl "http://localhost:3000/api/mocks/content-search/search?q=moskau"
  ```

- **`mockFetch`**, from the generator, is a `fetch` that answers the published mock's
  URLs in the browser and passes everything else on. Hand it to anything that takes a
  `fetch`. The [Viewer's Content Search demo](/docs/viewer#content-search) does:

  ```jsx
  import { mockFetch } from "docs/mocks/content-search/index.mjs";

  <Clover.Viewer
    iiifContent="https://nulib-ds.github.io/clover/mocks/content-search/manifest.json"
    request={{ fetch: mockFetch() }}
  />;
  ```

<Callout type="info">
  Clover 3.x's older newspaper mock (`/manifest/content-search/`) is unchanged.
  Its live service, `/api/fixtures/content-search/1`, works in `npm run dev`
  again: the docs build is a static export, and the export setting used to turn
  API routes off in development too.
</Callout>

### Changing it

The generator is `docs/mocks/content-search/index.mjs`; the OCR is
`docs/mocks/content-search/ocr.json` (words in reading order, `[text, x, y, w, h]`).
After changing either, run `npm run build:mocks` and commit `public/mocks/`. The OCR
pages are written compact, and Prettier leaves `public/mocks/` alone.

## Georeference: a township map

Northwestern University Libraries' scan of the _Map of the Township of Evanston, Cook
County, Illinois_, as a Manifest of one Canvas, with:

- the [Georeference Extension](https://iiif.io/api/extension/georef/) annotation its Meadow
  authoring tool stored (three control points, the whole image as its mask, a first-order
  polynomial transformation), on the Canvas's annotation page;
- a [navPlace](https://iiif.io/api/extension/navplace/) point naming Evanston, Illinois;
- the image from Northwestern's IIIF Image API (level 2, 7337 × 9833, CORS open).

| Resource | Published (static)                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------- |
| Manifest | [`/mocks/georeference/manifest.json`](https://nulib-ds.github.io/clover/mocks/georeference/manifest.json) |

It answers no query, so it is static only. The [Map](/docs/map) page draws it, warped
onto the map, and in a Viewer's Map tab. Its generator is
`docs/mocks/georeference/index.mjs`.

## Paged: a catalog in spreads

Northwestern University Libraries' record of the White Sewing Machine Company's
_Portfolio of illustrations showing the White bicycles : then and now_ (1896), a `paged`
Manifest of 31 Canvases (its covers and 29 pages), with:

- a `summary`, which the record has none of, written from its own fields (Publisher,
  Location, Date, the illustrators its Alternate Title names, Materials) and its pages,
  in under 30 words: "The White Sewing Machine Company of Cleveland issued this bicycle
  catalog in 1896. Color plates by Thulstrup, Mente, Veenfliet, and Clarke pair “Then”
  with “Now”; specifications describe four models.";
- `behavior: ["facing-pages"]` on Page 15. It is one image of a whole opening, a colour
  plate across both pages (9423 × 4694, twice a page's width), so it is shown alone and
  the pages after it pair as the book's openings do. The spreads run Front Cover, 1–2 …
  13–14, 15, 16–17 … 28–29, Back Cover. As published, the plate pairs with Page 16, and
  every opening after it is split;
- `structures`, which the record has none of: a Range for each of the catalog's sections,
  titled exactly as the catalog has it, by the heading printed on its page (its words,
  without the closing full stop), or, for a cover, by the Canvas's own label. Front Cover;
  Introduction; Specifications “White” 1896 Model A, B, C and D, each with its engraving;
  “White” Bearings (Crank Bearing, The Hubs); Important Features of the “White”, six
  headings, where those that share a page each name their region of it (`#xywh=`);
  Guaranty on “White” Bicycles; Tire Guarantees; Terms of Sale; Back Cover;
- on each plate that pairs a "Then" with a "Now" (Pages 4, 6, 18, 20, 22, 24 and 26, and
  the Back Cover), the two tagged where they are, as
  [Cookbook recipe 0021](https://iiif.io/api/cookbook/recipe/0021-tagging/) tags a
  fountain: "Then" round the inset scene and the word printed by it, "Now" round most of
  the picture, clear of its edges (on the Back Cover, the round scene below). Page 15
  prints "Now" with no "Then", so it has none;
- everything else as Northwestern's Digital Collections API published it on 14 October
  2026, apart from the ids of the Manifest and its Canvases, which are the mock's own;
- the images from Northwestern's IIIF Image API (level 2, CORS open).

## Transcripts: a film's captions and its transcript

The IIIF Cookbook's [recipe 0219](https://iiif.io/api/cookbook/recipe/0219-using-caption-file/),
_Lunchroom Manners_, a Manifest of one video Canvas (9 min 32 s), with:

- its English captions as the recipe publishes them, a `supplementing` WebVTT file
  labelled "Captions in WebVTT format";
- the film's transcript as plain text beside them, as the Canvas's `rendering`, which is
  how [recipe 0017](https://iiif.io/api/cookbook/recipe/0017-transcription-av/) gives a
  transcript. The file is the one
  [recipe 0253](https://iiif.io/api/cookbook/recipe/0253-using-transcript-file/)
  (Presentation 4) provides for the same film, with that recipe's label, "Transcript in
  plain text format", and its language, `en`;
- everything else as recipe 0219 publishes it, apart from the ids of the Manifest, its
  Canvas and their annotations, which are the mock's own;
- the video, the captions and the transcript from the Cookbook's own fixtures, at
  fixtures.iiif.io (CORS open).

So a viewer has both kinds of transcript to offer, the timed captions and the untimed
text: Clover's Transcript lists them as "EN" and "TXT".

## Page transcript: a newspaper's pages as text

The newspaper issue of the [Content Search mock](#content-search-20-a-newspaper-issue)
(the _Berliner Tageblatt_ of 16 February 1925, two pages), with each page's transcript as
plain text: a `text/plain` file in the Canvas's `rendering`, labelled "Text (OCR)" and in
German (`de`), as libraries publish a page's OCR text beside its image. It has no search
service and no OCR annotations, so the text files are the one way to the words.

Each file is the page's own OCR, as the Content Search mock reads it: its lines in
reading order, a line of the page a line of the file, with a blank line where the next
line jumps up a column or steps down more than 1.6 times the page's usual line pitch (a
new block). Nothing in it is typed by hand, so it reads as the OCR does, long s (ſ) and
misreadings included.

| --------------- | --------------------------------------------------------------------------------------------------------------- |
| Manifest        | [`/mocks/page-transcript/manifest.json`](https://nulib-ds.github.io/clover/mocks/page-transcript/manifest.json) |
| Page 1, as text | [`/mocks/page-transcript/text/p1.txt`](https://nulib-ds.github.io/clover/mocks/page-transcript/text/p1.txt)     |
| Page 2, as text | [`/mocks/page-transcript/text/p2.txt`](https://nulib-ds.github.io/clover/mocks/page-transcript/text/p2.txt)     |

In `npm run dev` it is live too, at
[`/api/mocks/page-transcript/manifest.json`](http://localhost:3000/api/mocks/page-transcript/manifest.json),
with ids under the dev server, so the text files it names are ones the dev server

copy the published files there again after a change.

## Standalone canvas: a map on its own

A Canvas published on its own, not in a Manifest: the one Canvas of Northwestern
University Libraries' record of Bartolomeo Borghi's map of the British Isles,
_L'Isole Britanniche_, as Clover 3.x's site publishes it
([`standalone-canvas.json`](https://samvera-labs.github.io/clover-iiif/canvas/standalone-canvas.json),
fetched on 19 October 2026), with:

- ids under the mock's own address for the Canvas, its painting page and annotation; its
  `partOf` still names the record's Manifest, from which a viewer can open it;
- `@context` for its `context` key, a slip in the published file;
- a `metadata` line it does not carry, its Contributor, as the record's Manifest publishes
  it: "Borghi, Bartolomeo, 1750-1821 (Cartographer)", "Costa, Agostino (Engraver)",
  "Borghi, Bartolomeo, 1750-1821 (Contributor)";
- an annotation page of its own, tagging Ireland where the map draws it
  (`xywh=600,4160,2180,2800`, read from the image), by the name the map prints there,
  "Irlanda", in Italian, as the map is;
- everything else as published, its label, summary, thumbnail and placeholder included;
- the image from Northwestern's IIIF Image API (level 2, CORS open).
